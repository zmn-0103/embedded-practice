## 确认缺陷

### P1：取消收藏响应期间新增的个人笔记会被列表刷新丢弃

路径：学习记录默认收藏列表（题库“只看收藏”使用同一组件）→ 打开题目和个人笔记 → 取消收藏 → 响应返回前继续编辑笔记 → 题目移出收藏列表。

`LibraryBrowser.tsx:101` 只在收藏请求开始前刷新保存笔记；请求期间笔记恢复可编辑。成功响应在 113 行触发列表刷新，417–425 行发现原题不在列表后清空选中，卸载详情。`PersonalNote.tsx:19–24` 注销并释放控制器；`note-controller.ts` 的 dispose 清除 500ms 自动保存计时器。该期间新增输入既未保存，也没有保留/失败提示。

新增探针只延迟真实 `library:set-favorite` 的成功响应，收藏写入、笔记编辑、列表读取及持久化仍走实际实现。两次独立运行都确认输入框已有新文字，放行响应后分别 11ms、10ms 消失；再等 700ms，经真实 readNote API 读取仍为旧笔记、revision=1。两次均在“新增输入必须保存”断言失败，未出现准备或定位失败。

证据：[两次观察](note-loss-observations.json)、[完整报告](note-race-01.json)、[日志](note-race-01.log)、[可重复探针](review.spec.ts)。

建议修复：让收藏请求及其引发的详情移除处于同一笔记保存保护范围；可在该期间锁定编辑，或在实际移除前再次保存并在失败时保留编辑器和原输入。补上响应延迟、保存失败及“只看收藏”组合回归。只在发请求前保存一次不够。
