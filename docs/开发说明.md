## 安装、开发与预览

以下PowerShell命令均在仓库根`E:/My_Projects/embedded-practice`执行。初次安装使用锁文件，不混用包管理器：

```powershell
npm ci
```

首次安装需要下载开发依赖和Electron；`postinstall`执行`electron-builder install-app-deps`准备原生模块。失败时先核对版本、下载和本机环境，不以占位数据库绕过。

开发运行和手动预览也使用独立目录。在新的PowerShell窗口中执行：

```powershell
$taskDataDirectory = Join-Path ([System.IO.Path]::GetTempPath()) ('embedded-practice-manual-' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $taskDataDirectory | Out-Null
$env:EMBEDDED_PRACTICE_TEST_DATA_DIR = $taskDataDirectory
try {
  npm run dev
} finally {
  Remove-Item Env:\EMBEDDED_PRACTICE_TEST_DATA_DIR -ErrorAction SilentlyContinue
}
```

`npm run dev`启动开发服务器及真实桌面窗口。预览已有产物时先执行`npm run build`，再在上述独立数据环境中把`npm run dev`换成`npm start`；预览使用构建页面。测试目录在本轮结束后按实际需要保留或清理，不能把正式学习目录填入环境变量。

## 静态、单元与桌面检查

| 命令 | 覆盖范围与前提 |
| --- | --- |
| `npm run check` | TypeScript类型与源码/配置格式；不会格式化用户计划书 |
| `npm test` | `tests/unit`单元套件；不表示Electron或个人库验收 |
| `npm run build` | 类型检查及生产`out/`构建；不会生成完整Windows程序 |
| `npm run test:desktop` | 先构建，再用开发Electron和构建页面运行development项目 |
| `npm run test:packaged` | 使用完整免安装EXE运行packaged项目；必须显式设置目标 |

桌面帮助器为每个场景新建系统TEMP目录，传入`EMBEDDED_PRACTICE_TEST_DATA_DIR`，结束时按父目录和前缀检查清理。不要传入正式或日常开发数据目录。纯SQLite测试、组件检查、Electron自动化、原生系统操作、NSIS安装、DPI/IME、性能与人工体验分别记录；替身对话框或故障注入应明示，构建和截图不能代替其他验收。

下例为**当前EXE的题库定向检查**，显式目标与独立报告同时指定；每次运行生成新目录，不覆盖旧结果：

```powershell
$env:EMBEDDED_PRACTICE_PACKAGED_EXECUTABLE = 'E:\My_Projects\embedded-practice\release\V0.0.3-20261030.1\win-unpacked\embedded-practice.exe'
if (-not (Test-Path -LiteralPath $env:EMBEDDED_PRACTICE_PACKAGED_EXECUTABLE -PathType Leaf)) { throw '指定EXE不存在，停止检查。' }
$taskReportDirectory = Join-Path (Get-Location) ('output/validation-' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $taskReportDirectory | Out-Null
$env:PLAYWRIGHT_JSON_OUTPUT_FILE = Join-Path $taskReportDirectory 'packaged.json'
try {
  npm run test:packaged -- tests/e2e/v003-bank.spec.ts --reporter=list,json --output="$taskReportDirectory/artifacts"
} finally {
  Remove-Item Env:\EMBEDDED_PRACTICE_PACKAGED_EXECUTABLE -ErrorAction SilentlyContinue
  Remove-Item Env:\PLAYWRIGHT_JSON_OUTPUT_FILE -ErrorAction SilentlyContinue
}
```

需要development项目时，先构建，再以同样的新报告目录、`PLAYWRIGHT_JSON_OUTPUT_FILE`和`--output`运行`node node_modules/@playwright/test/cli.js test --project=development --reporter=list,json`，并附上明确的`--output`路径。需要其他定向场景时替换测试文件；需要完整套件时先核对旧包依赖，去掉文件参数不代表缺失的旧兼容目标已恢复。报告器须用`--reporter=list,json`覆盖配置中的固定默认JSON文件；完整文件路径用`PLAYWRIGHT_JSON_OUTPUT_FILE`，不要用`PLAYWRIGHT_JSON_OUTPUT_NAME`替代。

新增`.mjs`、Python等辅助脚本不自动包含在`npm run check`的TypeScript/格式范围；按脚本语言执行必要语法/格式检查。M5、findability、分类性能与旧题库选集脚本含固定样本、页面或旧EXE假设，历史调用及限制见[沿革](history/构建与运行沿革.md)，在核对当前兼容性之前不作为本版常规检查。

## 构建与打包

构建输出为`out/main`、`out/preload`和`out/renderer`。打包使用新目录，现成V0.0.3和封存证据不覆盖；下例先构建，再用项目已安装的同版本Electron分发生成Windows x64完整免安装目录：

```powershell
npm run build
$taskPackageDirectory = 'release/manual-' + [guid]::NewGuid().ToString('N')
node node_modules/electron-builder/cli.js --win --x64 --dir --publish never --config.electronDist=node_modules/electron/dist --config.directories.output=$taskPackageDirectory
```

新目标是`$taskPackageDirectory/win-unpacked/embedded-practice.exe`。后续测试应将`EMBEDDED_PRACTICE_PACKAGED_EXECUTABLE`设置为该EXE的绝对路径，并重新核对构建/结构；不能仍指向上一个已测包。

[构建配置](../electron-builder.yml)的默认输出目录为`release`，`npm run pack:dir`和`npm run pack:win`会使用该默认目录。需要NSIS任务时，在上例明确新目录的builder命令中用`--win nsis --x64`替代`--win --x64 --dir`；仅在相应交付授权下执行。命令均带`--publish never`，现有配置未启用代码签名。生成NSIS不表示已完成安装、升级、卸载重装或新电脑验收。

ASAR白名单包含`out/**/*`、`package.json`及`docs/licenses/**/*`，原生`.node`单独解包；测试、备份与其他开发文档不在该白名单。运行文件与第三方原许可需要随完整程序保留，不能依据第三方许可推断项目整体已开源；项目仍为`UNLICENSED`。

## 数据位置、诊断与保护

| 运行形态 | 默认数据位置 |
| --- | --- |
| 完整免安装或安装版 | `%APPDATA%/embedded-practice/` |
| 开发与预览 | `%APPDATA%/embedded-practice-dev/` |
| 自动化、手动检查与性能检查 | 环境变量`EMBEDDED_PRACTICE_TEST_DATA_DIR`指定的新建独立绝对路径 |

主库为`practice.sqlite3`，当前结构17；Chromium会话数据在`session/`，诊断日志在`logs/application.log`。正常使用可从“设置与数据 → 数据位置”查看实际路径并打开受控目录；界面版本、数据库结构和实际目录需一起核对。普通报错先保留原文件与日志，不删除数据库、WAL或伴随文件来绕过问题。

常规启动对已知结构1～16先创建并校验一致性保护备份，再以事务升级到17；备份失败停止，迁移/外键失败回滚。损坏、非空但缺少应用标识、标识不符或不受支持结构应停止使用并保留文件，不自动重建空库。旧程序不能据此获得结构17兼容性。完整备份/恢复的目标保护、预览凭据、关闭连接、替换回退与重启规则见[数据保护与桌面边界](数据保护与桌面边界.md)。测试恢复只使用独立副本。

正常关闭先等待最新输入及在途保存确认，不能确认时默认返回窗口；强制结束只承诺恢复已确认保存内容。数据故障应记录构建、实际路径、错误与操作阶段，并按契约诊断，不能把页面加载前强制退出的启动失败直接解释为库损坏。

`upgrade-v003-desktop.mjs`、`deploy-v003-bank.mjs`、`reset-v003-desktop.mjs`是2026-10-30用户明确授权的交付专用脚本。其无新增备份升级、实际个人目录替换与清空仅属于当次授权，**不是常规升级、测试或故障恢复步骤，不得未经新的明确授权重复apply**。既有备份、原始资料和正常保护机制保持；当次过程查[需求实施历史](history/需求变更中的实施记录.md#req-23)、[构建沿革](history/构建与运行沿革.md#build-01)及[重置原始报告](evidence/v003-reset-20261030/README.md)。
