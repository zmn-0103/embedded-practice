## 本批实现

- 作答占位提示显式使用主题`--muted`，不透明度为1；不修改主题格式、正文色或字号。五内置主题的明暗组合按空白输入实际颜色测量，不能将本次测量扩为完整无障碍认证。
- 题库按“选择范围→设置条件→查看结果”组织，分类/专题/归档仍即时生效，附加条件仍通过“筛选题库”显式应用。草稿摘要与当前生效摘要分开；只有成功读取对应请求后才显示生效范围和题数。清空入口和说明集中在结果区，普通题库清空全部范围与附加条件；学习记录内清空只重置下方列表附加条件，保留上方统计范围。作答仍通过既有“开始练习”页设置，不将浏览条件隐式加入固定队列。
- 练习底栏将答题阶段与保存状态并列；揭晓前突出“查看参考答案”，揭晓后说明自评会保存并推进、末题会完成本轮。自评按钮沿用已有语义颜色，顶部返回为次要操作，跳过/暂不评价弱化，失败时突出原保存/操作重试。保留原返回按钮名称和位置，不新增独立提交、自评状态或业务接口。

本批只做上述三项及其必要换行保护。第二批的高缩放空间优化、概览行动入口、规划板块和其他说明统一尚未实施；跨显示器真实鼠标拖动仍待确认，不改窗口DPI处理。沿用公共组件、语义变量、本机字体和15～22px正文字号，不引入新组件库、在线资源或依赖。

## 用户结论原文

UI 的优化方向可以归纳为：**保留现有工作台结构和多主题体系，优先改善信息层级、操作清晰度和文字可读性，再完善小窗口与高缩放下的布局。** 目前没有证据表明需要整体重做视觉风格。

结合前面的页面审查与实际验证，建议按以下顺序推进：

| 优先级 | 优化方向 | 具体建议 | 预期改善 |
|---|---|---|---|
| **P0** | **修复输入提示文字的对比度** | 为答案输入框的占位文字明确使用主题中的语义颜色，逐一验证五种主题的浅色、深色模式。 | 输入提示更容易看清，尤其是深色主题。 |
| **P1** | **整理题库页面的筛选区** | 按“选择范围 → 设置条件 → 查看结果 → 开始练习”组织内容；让当前生效的筛选条件、结果数量和清除入口更集中，明确“清除”的作用范围。 | 用户能迅速判断“当前筛出了什么、为什么只剩这些题、下一步怎么做”。 |
| **P1** | **强化练习页面的操作层级** | 结合答题阶段突出当前主要操作，区分“查看参考答案”“保存并继续”“保存后返回”等动作；统一按钮位置、主次样式和状态反馈。 | 减少寻找按钮和误判操作结果，让注意力回到答题内容。 |
| **P1** | **改善小窗口与高缩放布局** | 优先压缩辅助信息和操作区占用，允许按钮合理换行，保证题目、答案输入框和主要操作都有可用空间。 | 在大字号、高缩放情况下，仍然可以舒适地阅读和输入。 |
| **P2** | **区分可用板块与规划板块** | 让已有内容的板块与尚未开放的板块在状态文字、视觉权重和点击反馈上有明显区别。 | 避免用户把规划入口误认为已经可以使用。 |
| **P2** | **让概览页更突出下一步行动** | 将“继续当前练习”“开始新练习”等入口放在更清晰的位置，统计信息作为辅助；区分首次使用、已有数据和存在未完成练习的状态。 | 打开应用后，更容易直接进入当前任务。 |
| **P2** | **统一设置、记录页的说明与反馈** | 统一筛选、重置、清除、保存等用词；明确设置是否已经生效；让空状态、无匹配结果和加载失败各自提供对应的下一步。 | 减少理解成本，避免用户不确定操作是否完成。 |

这里需要区分**已经确认的问题**和**设计改进建议**：

- **已经确认：输入框占位文字对比度不足。** 五种主题、两种明暗模式共十种组合中，八种低于普通文字采用的 4.5∶1 检查标准；最低约为 **3.20∶1**。这是最适合先处理的小范围问题。
- **已有实际依据：高缩放时内容空间明显收紧。** 程序缩放到 200% 时，底部操作区占用较多空间。虽然已检查的主要操作仍可使用，但阅读和输入空间值得继续优化。
- **仍需确认：跨显示器后的窗口尺寸变化。** 在 100% 与 150% Windows DPI 显示器间移动时，观察到一次窗口尺寸放大；由于涉及自动化移动方式，目前不能直接认定为应用缺陷。应先补充真实鼠标拖动验证，再决定是否调整窗口行为。
- **其余属于设计审查建议。** 题库、概览和按钮层级的调整有助于提高易用性，但不能把这些建议描述成已经通过用户测试确认的问题。

所有调整都应继续复用现有公共组件、主题变量和字号约定。主题切换应保持稳定的布局、按钮含义和状态表达，避免不同主题逐渐形成不同的操作习惯。

**建议第一批只做三件事：修复占位文字对比度、整理题库筛选区、明确练习页操作层级。** 第二批再处理高缩放布局，以及概览、板块状态和说明文字。这样每一批都能在真实页面上清楚比较改进前后的效果；现有 **42 项运行与交互检查通过**，也可以作为后续回归的基础，但不代表全部 UI 或 Windows DPI 场景已经验收。
