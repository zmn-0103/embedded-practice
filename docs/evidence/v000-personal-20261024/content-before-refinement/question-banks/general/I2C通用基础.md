## i2c-general-001 | 区分 7 位设备地址与线上地址字节

标签：I2C, 设备寻址, 计算题
难度：基础

### 题目

某 I2C 目标设备的 7 位地址为 `0x29`。采用普通 7 位寻址，START 后的地址字节按“7 位地址在高 7 位，最低位 R/W：写为 0、读为 1”组成，不讨论 10 位寻址或特殊地址。

请计算写方向、读方向的线上地址字节。若换用一个未说明参数格式的驱动接口，能否据此认定它一定要传 `0x29`，或者一定要传左移后的值？请解释。

### 参考答案

**核心结论：** 写方向为 `(0x29 << 1) | 0 = 0x52`；读方向为 `(0x29 << 1) | 1 = 0x53`。二者的 7 位目标地址相同，差别在读写方向。

**必要解释：** 7 位设备地址、线上地址字节和驱动接口参数是三个层面的概念。有的接口接收原始 7 位地址并自行编码，有的要求调用者预先移位，还可能另传方向参数，必须查接口契约。

**常见误区：** 看到数据手册或分析仪显示一个数就直接作为接口参数，或重复移位；应先确认文档显示的是 7 位地址还是包含 R/W 的 8 位值。

#### 技术依据

[NXP UM10204 Rev.7.0，第 3.1.10 节：目标地址与 R/W 位](https://www.nxp.com/docs/en/user-guide/UM10204.pdf)。驱动参数由具体接口决定，不从协议位格式推定某个库的行为。

## i2c-general-002 | 用重复 START 组织一次寄存器读取

标签：I2C, 消息边界, 时序分析, 情景分析
难度：进阶

### 题目

单控制器 I2C 总线上，目标设备的 7 位地址为 `0x29`。器件协议明确要求：先写入一个 8 位寄存器指针 `0x10`，不发送 STOP，使用重复 START 切换为读方向，再连续读取 2 字节；内部地址自动递增。最后一个字节由控制器发送 NACK，随后 STOP。假设目标设备正常应答，线路与时序满足要求。

请写出完整事务，标明每个地址或数据字节的方向，以及 ACK/NACK 由谁产生。为什么不能把“寄存器指针、地址递增、重复 START”视为所有 I2C 器件都相同的规定？

### 参考答案

**核心结论：** 事务为：START → 控制器发 `0x52` → 目标 ACK → 控制器发 `0x10` → 目标 ACK → 重复 START → 控制器发 `0x53` → 目标 ACK → 目标发第 1 字节 → 控制器 ACK → 目标发第 2 字节 → 控制器 NACK → STOP。

**必要解释：** 字节的接收方在第九个时钟应答，控制器提供时钟。读地址仍由控制器发送，因此其 ACK 来自目标；读数据的接收方则变成控制器。末字节 NACK 表示不再继续读取，本题中是正常收尾。

**成立条件：** 重复 START 在不先释放总线的情况下开始新的寻址阶段。寄存器指针宽度、递增方式及是否允许先 STOP 再读，须遵循目标器件协议；本题已明确要求组合事务。

#### 技术依据

[NXP UM10204 Rev.7.0，第 3.1.4、3.1.6、3.1.10 节及图 13：重复 START、应答与组合格式](https://www.nxp.com/docs/en/user-guide/UM10204.pdf)。寄存器行为是题设条件，不是对所有器件的推广。
