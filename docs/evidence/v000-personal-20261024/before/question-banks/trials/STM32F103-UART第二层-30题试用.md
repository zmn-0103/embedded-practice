## uart2-019 | TXE 与发送完成状态

标签：STM32F103, UART, 状态标志, 发送, 判断题
难度：基础

### 题目

TXE=1 就意味着最后一个停止位已经从 TX 引脚发送完毕。

### 参考答案

**错误**

TXE 只表示发送数据寄存器为空，数据可能仍在移位寄存器中发送。

## uart2-020 | TC 与最后一帧完成

标签：STM32F103, UART, 状态标志, 发送, 判断题
难度：基础

### 题目

TC=1 时，表示发送数据寄存器与移位寄存器均为空，最后一帧已经发送完成。

### 参考答案

**有条件成立，不能仅凭 TC=1 断言刚完成了一次有效发送。**

在已经启动有效发送、并按手册规定处理了此前 TC 状态的上下文中，TC=1 才用于确认相应发送已经完成；连续发送时应观察最后一帧的完成状态。它与只表示发送数据寄存器可继续写入的 TXE 不同。

#### 适用条件与来源

STM32F103 的 USART_SR 复位值为 0x00C0，TC 复位后就是 1，因此复位后读到 TC=1 不能证明发过数据。TC 的规定清除序列涉及读 SR 后写 DR，另有按手册限定使用的写 0 路径；不能把任意读改写当成通用清标志操作。依据：[ST RM0008 Rev21，27.6.1](https://www.st.com/resource/en/reference_manual/cd00171190.pdf)。本题未做发送波形或板上验证，仍待用户审阅。

## uart2-025 | volatile 与读改写原子性

标签：STM32F103, UART, C语言, 并发与原子性, 判断题
难度：进阶

### 题目

`volatile` 能够保证寄存器读—改—写操作具有原子性。

### 参考答案

**错误**

`volatile` 不能保证复合读—改—写操作具有原子性，也不能自动解决并发问题。

#### 适用条件与来源

本机 GNU Tools for STM32 的 GCC 13.3.1，在 Cortex-M3、Thumb、普通有效且按 32 位对齐的可读写对象前提下，分别以 -O0、-O2 编译独立样例。-O2 中单次赋值生成 STR，而 `*reg |= mask` 生成 LDR、ORRS、STR，整个读改写仍是多条指令；中断若在读与写之间修改同一对象，随后写回可能覆盖该修改。不能由“某次访问是一条指令”推导整个复合操作原子。

实际并发控制还取决于共享对象、访问者和寄存器语义，应采用符合该场景的临界区或硬件原子置位/清位机制；特殊状态寄存器不因加了 volatile 就适合读改写。依据：[GCC volatile 说明](https://gcc.gnu.org/onlinedocs/gcc/Volatiles.html)与本批独立编译及反汇编记录，后者的完整来源见仓库 UART 技术核对文档。这只补充所列工具链和样例的依据，没有运行样例、验证其他编译器或代替板上并发实验，仍待用户审阅。

## uart2-029 | BRR 计算：72 MHz、115200 baud

标签：STM32F103, UART, 波特率, 寄存器, 计算题
难度：进阶

### 题目

已知：

- USART1 输入时钟：72 MHz
- 目标波特率：115200 baud
- 过采样倍数：16

请计算：

1. USARTDIV
2. 整数部分
3. 小数部分
4. BRR 的最终值

写出计算过程。

### 参考答案

计算公式：

`USARTDIV = fCK / (16 × baud)`

代入：

`USARTDIV = 72000000 / (16 × 115200)`

得到：

`USARTDIV = 39.0625`

整数部分为 39，即 `0x27`。

小数部分为 0.0625：

`0.0625 × 16 = 1`

因此：

`BRR = (39 << 4) | 1 = 0x0271`

## uart2-030 | CR1 解析：收发、字长与校验

标签：STM32F103, UART, 寄存器, 帧格式, 读寄存器
难度：基础

### 题目

已知：

`CR1 = 0x200C`

请分析：

1. UE、TE、RE 分别是什么状态？
2. M、PCE、PS 是什么状态？
3. 是否启用了 RXNE 中断？
4. 该配置是否符合普通 8N1 收发的 CR1 要求？

### 参考答案

`CR1 = 0x200C`

二进制置位情况：

- bit 13（UE）= 1。
- bit 3（TE）= 1。
- bit 2（RE）= 1。
- bit 12（M）= 0。
- bit 10（PCE）= 0。
- bit 9（PS）= 0。
- bit 5（RXNEIE）= 0。

因此，该配置启用了 USART、发送器和接收器，没有启用奇偶校验，也没有启用 RXNE 中断源，符合普通 8N1 收发的 CR1 配置要求。

#### 适用条件与来源

这里仅说明 CR1 中的字长、校验和收发状态。要确认完整的普通 8N1，还须检查 CR2 的 STOP=00（1 个停止位）及实际通信模式；波特率、时钟和引脚配置也需要另行核对。PCE=0 时，PS 位不产生启用奇偶校验的效果。不能只看 CR1=0x200C 就认定整套串口配置正确。依据：[ST RM0008 Rev21，27.6.4～27.6.5](https://www.st.com/resource/en/reference_manual/cd00171190.pdf)和 ST SPL V3.5.0 的 USART_Init；仍待用户审阅。

## uart2-031 | CR2 STOP 字段与停止位

标签：STM32F103, UART, 寄存器, 帧格式, 位运算
难度：基础

### 题目

CR2 的 STOP 字段位于 bit 13:12。

请回答：

1. STOP=`00` 表示什么？
2. STOP=`01` 表示什么？
3. STOP=`10` 表示什么？
4. 如果只修改 STOP 字段，为什么不能直接用新字段值覆盖整个 CR2？

### 参考答案

| STOP | 含义       |
| ---- | -------- |
| 00   | 1 个停止位   |
| 01   | 0.5 个停止位 |
| 10   | 2 个停止位   |
| 11   | 1.5 个停止位 |

STOP 是多位字段。直接覆盖整个 CR2 可能破坏其他控制位。

修改字段时，应先清除 STOP 对应的位，再设置目标值，同时保留其他需要保留的位。

#### 适用条件与来源

上表是字段编码，不代表每个外设实例、每种模式都支持全部取值。RM0008 明确指出 UART4、UART5 不支持 0.5 和 1.5 个停止位；Smartcard 的停止位配置另有模式要求，普通异步通信不能仅凭这张编码表照搬。应结合具体 USART/UART 实例、当前模式和对端帧格式选择。依据：[ST RM0008 Rev21，27.6.5 与 27.3.11](https://www.st.com/resource/en/reference_manual/cd00171190.pdf)；仍待用户审阅。

## uart2-032 | SR 解析：TXE、TC 与 RXNE

标签：STM32F103, UART, 寄存器, 状态标志, 位运算
难度：基础

### 题目

已知：

`SR = 0x00A0`

请判断：

1. TXE 是否置位？
2. TC 是否置位？
3. RXNE 是否置位？

写出对应的掩码判断过程。

### 参考答案

已知：

`SR = 0x00A0`

TXE 掩码：

`1 << 7 = 0x0080`

`0x00A0 & 0x0080 = 0x0080`

因此 TXE=1。

TC 掩码：

`1 << 6 = 0x0040`

`0x00A0 & 0x0040 = 0`

因此 TC=0。

RXNE 掩码：

`1 << 5 = 0x0020`

`0x00A0 & 0x0020 = 0x0020`

因此 RXNE=1。

最终结果：TXE=1、TC=0、RXNE=1。

## uart2-033 | USART 标准外设库函数的职责

请分别解释以下函数的作用，以及它们是否会自动等待状态标志：

3. `USART_SendData()`
4. `USART_ReceiveData()`
5. `USART_GetFlagStatus()`
6. `USART_ITConfig()`
7. `USART_DMACmd()`

### 参考答案

| 函数                    | 主要作用                 | 是否自动等待状态标志 |
| --------------------- | -------------------- | ---------- |
| USART_Init()          | 根据结构体配置 USART 通信参数   | 否          |

| USART_ReceiveData()   | 读取接收数据寄存器            | 否          |
| USART_GetFlagStatus() | 查询指定状态标志             | 否，只查询      |
| USART_ITConfig()      | 配置 USART 内部中断使能位     | 否          |
| USART_DMACmd()        | 使能或关闭 USART 的 DMA 请求 | 否          |

调用者必须理解每个函数的职责，并负责协调状态检查、数据处理和外设时序。

## uart2-034 | USART 状态标志的清除方式

标签：STM32F103, UART, 状态标志, 寄存器, 错误处理
难度：进阶

### 题目

请说明以下标志的含义与清除方式：

1. TXE
2. TC
3. RXNE
4. IDLE
5. ORE
6. FE
7. NE
8. CTS
9. LBD

特别说明：为什么不能把所有标志都统一交给 `USART_ClearFlag()` 处理？

### 参考答案

| 标志   | 含义           | 清除方式                               |
| ---- | ------------ | ---------------------------------- |
| TXE  | 发送数据寄存器为空    | 写入 DR 后由硬件清除                       |
| TC   | 发送完成         | 按手册规定的方式清除，例如读取 SR 后写 DR，或向 TC 写 0 |
| RXNE | 接收数据寄存器非空    | 通常读取 DR 清除                         |
| IDLE | 接收线路空闲事件     | 先读 SR，再读 DR                        |
| ORE  | 接收溢出错误       | 先读 SR，再读 DR                        |
| FE   | 帧错误          | 先读 SR，再读 DR                        |
| NE   | 噪声错误         | 先读 SR，再读 DR                        |
| CTS  | CTS 状态变化     | 向对应标志写 0                           |
| LBD  | LIN Break 检测 | 向对应标志写 0                           |

不能把所有标志统一交给 `USART_ClearFlag()`，因为不同标志具有不同的硬件清除语义。STM32F1 SPL 的该函数只允许清除特定标志；错误标志和 IDLE 等必须遵循手册规定的读取序列。

## uart2-035 | USART1 初始化的依赖与顺序

标签：STM32F103, UART, 初始化, GPIO, 流程题
难度：进阶

### 题目

请从硬件依赖关系出发，写出 USART1 默认映射下的主要初始化步骤，并说明 RCC、GPIO、BRR、CR1、CR2、CR3 分别负责什么。

### 参考答案

应先完成依赖准备，再开放对应收发事件。以下是初始化时的依赖安排，不是适用于所有模式的唯一寄存器写入顺序：

1. 确认实际时钟树和 USART1 的 PCLK2，使能所需 GPIOA、USART1 时钟；需要修改映射时同时准备 AFIO 时钟。
2. 默认映射下配置 PA9 为复用推挽输出、PA10 为适合板卡接线的输入模式。若采用重映射，改按实际引脚配置，不继续使用默认引脚假设。
3. 按手册规定配置 BRR、CR1 的字长和校验、CR2 的停止位、CR3 的流控等参数；准备期间保持尚未就绪的中断源和 DMA 请求关闭，收发使能按实际配置步骤控制。
4. 使用中断时，先准备接收缓存、状态变量、正确的中断入口以及 NVIC 通道和优先级，再开放相应事件；需按真实事件处理遗留标志，不无条件读取 DR 丢弃有效数据。
5. 使用 DMA 时，先准备缓存和 DMA 通道的方向、地址、长度及状态；在通道已准备并按要求使能后，再开放 USART 对应 DMA 请求，不能用 USART_DMACmd 代替 DMA 控制器配置。
6. 按选定模式完成 USART、收发器和对应请求的使能，并与发送方约定开始通信的时机，避免初始化窗口内已有外部数据到达而无人接收。
7. 通过状态标志与实际通信检查配置；轮询方式不必为了套用此表增加 NVIC 或 DMA。

各模块职责：

- RCC：提供外设时钟。
- GPIO：配置引脚模式。
- BRR：设置波特率分频。
- CR1：设置核心通信参数和收发控制。
- CR2：设置停止位及特殊模式。
- CR3：设置 DMA、硬件流控等高级功能。

#### 适用条件与来源

原答案中“先使能 USART，再配置 NVIC 或 DMA”不再作为通用固定顺序。上述“先准备再开放请求”由实际依赖关系推导：SPL V3.5.0 的 USART_ITConfig 只设置外设中断控制位，USART_DMACmd 只设置 USART DMA 请求位，两者都不替调用者准备处理入口、NVIC、DMA 通道或缓存。硬件流程另见[ST RM0008 Rev21，13.3 与第27章](https://www.st.com/resource/en/reference_manual/cd00171190.pdf)。本题没有执行中断或 DMA 收发实验，仍待用户审阅。

## uart2-036 | 发送时序：从写 DR 到 TC

标签：STM32F103, UART, 发送, 时序, 流程题
难度：基础

### 题目

请按照硬件执行顺序，描述软件发送一个字节时，从写入 DR 到 TC 置位的主要过程。

解释 TXE 为什么可能早于 TC 置位。

### 参考答案

1. 软件确认 TXE=1。
2. 软件向 DR 写入数据。
3. TXE 清零。
4. 硬件将数据转移到发送移位寄存器。
5. TXE 重新置位，允许写入下一份数据。
6. 移位寄存器按照串行帧格式发送数据。
7. 最后一帧发送完成且发送数据寄存器为空时，TC 置位。

TXE 关注发送数据寄存器是否可用；TC 关注整个发送过程是否完成。因此 TXE 可以早于 TC 置位。

## uart2-037 | 接收时序：从 RX 到读 DR

标签：STM32F103, UART, 接收, 时序, 流程题
难度：基础

### 题目

请描述一个字节从 RX 引脚进入 USART，到软件读取 DR 的主要过程。

说明 RXNE 的产生条件、读取 DR 的作用，以及 ORE 可能如何产生。

### 参考答案

1. USART 检测 RX 引脚上的起始位。
2. 硬件按配置的波特率采样数据。
3. 硬件完成数据帧接收。
4. 接收数据进入 DR，RXNE 置位。
5. 软件检查 RXNE 后读取 DR。
6. 正常读取后 RXNE 清除。

如果旧数据没有及时读取，而新数据又完成接收，可能产生 ORE。软件应及时取走数据，并按手册规定处理错误标志。

## uart2-038 | 从标准外设库追踪寄存器行为

标签：STM32F103, UART, 标准外设库, 寄存器, 概念题
难度：基础

### 题目

请解释以下调用链的关系：

应用程序 → SPL 函数 → 寄存器访问 → USART 硬件。

为什么只记住库函数名称，不足以满足第二层的学习要求？

### 参考答案

应用程序调用 SPL 函数，SPL 函数访问 CMSIS 定义的寄存器，CPU 再通过总线访问 USART 外设，最终由硬件完成相应操作。

- 函数实际修改了哪些寄存器。
- 为什么需要等待 TXE 或 RXNE。
- 为什么某些状态标志需要特殊清除顺序。
- 初始化参数如何转化为寄存器配置。
- 硬件异常发生时应该检查什么。

第二层要求能够从寄存器与手册出发解释硬件行为。

## uart2-039 | CR1 位掩码与组合使能

标签：STM32F103, UART, 寄存器, 位运算, 计算题
难度：基础

### 题目

请计算以下掩码的十六进制值：

1. UE：bit 13
2. TE：bit 3
3. RE：bit 2
4. RXNEIE：bit 5
5. TXEIE：bit 7
6. TCIE：bit 6

然后回答：如果只需要启用 UE、TE、RE，应该将哪些位设置为 1？

### 参考答案

| 位            | 掩码     |

## uart2-040 | 多位字段的读改写与风险

标签：STM32F103, UART, 寄存器, 位运算, 并发与原子性
难度：进阶

### 题目

假设某寄存器中的目标字段位于 bit 5:4，现在需要将该字段设置为二进制 `10`。

请说明：

1. 目标字段掩码是多少？
2. 应先清除哪些位？
3. 为什么不能简单地对寄存器执行 `REG |= VALUE`？
4. 普通读—改—写操作有哪些潜在风险？

### 参考答案

目标字段为 bit 5:4。

字段掩码：

`MASK = 0b00110000 = 0x30`

目标字段值为二进制 `10`，放入 bit 5:4 后：

`VALUE = 0b00100000 = 0x20`

常规读—改—写表达式：

`REG = (REG & ~MASK) | VALUE`

不能简单执行 `REG |= VALUE`，因为原字段中可能已有 1，按位或无法将原来的 1 清零。

普通读—改—写还可能存在并发修改、非原子操作，以及对具有读写副作用的寄存器产生意外影响等风险。

## uart2-041 | BRR 计算：72 MHz、9600 baud

标签：STM32F103, UART, 波特率, 寄存器, 计算题
难度：进阶

### 题目

假设 USART1 输入时钟仍为 72 MHz，但目标波特率改为 9600 baud。

请计算：

1. USARTDIV
2. BRR 的整数部分
3. BRR 的小数部分
4. 最终 BRR 值

说明与 115200 baud 相比，BRR 为什么发生变化。

### 参考答案

已知：

`fCK = 72000000`

`baud = 9600`

计算：

`USARTDIV = 72000000 / (16 × 9600) = 468.75`

整数部分：

`468 = 0x1D4`

小数部分：

`0.75 × 16 = 12 = 0xC`

因此：

`BRR = (468 << 4) | 12 = 0x1D4C`

波特率越低，在输入时钟不变的情况下，所需分频系数越大，因此 BRR 的数值随之变化。

## uart2-043 | 故障排查：TX 无输出

标签：STM32F103, UART, 发送, GPIO, 故障排查
难度：综合

### 题目

USART1 初始化后，程序已经执行发送函数，但电脑收不到任何字符。

请从以下层次分析可能原因：

1. RCC
2. GPIO
3. AFIO 映射
4. USART 控制寄存器
5. BRR 与帧格式
6. 物理连接

### 参考答案

建议按层次检查：

1. **RCC：** GPIOA、USART1 时钟是否使能。
2. **GPIO：** PA9 是否配置为复用推挽输出。
3. **AFIO：** USART1 是否采用默认映射，是否存在重映射配置不一致。
4. **USART：** UE、TE 是否置位，初始化是否正确。
5. **BRR 与帧格式：** 是否使用正确的 PCLK2，波特率和数据帧参数是否匹配。
6. **物理连接：** STM32 TX 是否连接到 USB 转 TTL 的 RX，双方是否共地。
7. **软件流程：** 程序是否实际执行到发送逻辑，TXE 是否正常变化。

#### 适用条件与来源

上述 GPIOA、PA9 排查以 USART1 默认映射为前提；USART1 重映射后 TX/RX 改为 PB6/PB7，应核对 AFIO_MAPR、GPIOB 时钟和实际板卡接线。也要核对转接器信号电平与 MCU 管脚条件是否兼容，不能只凭“USB 转串口”名称推断电气接口正确。TXE 或函数已经执行不能证明引脚波形、接线或电脑端配置正常。依据：[ST RM0008 Rev21，9.3.8、9.4.2 与第27章](https://www.st.com/resource/en/reference_manual/cd00171190.pdf)。这些是待验证的排查项，不是已确认根因，仍待用户审阅。

## uart2-044 | 故障排查：TXE 正常、TC 未置位

## uart2-045 | 故障排查：接收出现 ORE

标签：STM32F103, UART, 接收, 错误处理, 故障排查
难度：进阶

### 题目

USART1 连续接收数据时出现 ORE。

请分析：

1. ORE 的产生条件。
2. 为什么扩大软件数组容量不一定解决问题？
3. 应如何处理硬件标志与软件缓冲区？
4. 清除错误标志后，是否能够恢复已经丢失的数据？

### 参考答案

ORE 可能在旧接收数据尚未被读取，而新数据又完成接收时产生。

扩大软件数组容量只能缓解软件缓冲区空间不足，不能直接解决 USART 硬件接收数据未及时读取的问题。

正确思路：

1. 及时读取 DR。
2. 检查程序是否长时间阻塞。
3. 检查接收处理是否及时。
4. 必要时考虑中断或 DMA。
5. 区分硬件 ORE 与软件数组溢出。
6. 按手册规定清除错误标志，并恢复接收流程。

清除 ORE 不能恢复已经丢失的数据。

## uart2-047 | 故障排查：接收数据乱码

标签：STM32F103, UART, 波特率, 接收, 故障排查
难度：综合

### 题目

电脑发送字符后，STM32 观察到的数据不符合预期。

请从时钟、BRR、数据帧格式、GPIO、物理连接和接收逻辑六个方面分析可能原因。

### 参考答案

- **时钟：** 确认实际 PCLK2。
- **BRR：** 根据实际输入时钟重新计算波特率。
- **帧格式：** 检查数据位、校验位和停止位。
- **GPIO：** 检查 PA10 的输入模式与 USART1 映射。
- **物理连接：** 检查 TX/RX 交叉连接、共地及信号电平。
- **接收逻辑：** 检查读取 DR 的时机、数据类型、缓冲区索引和数据处理过程。

#### 适用条件与来源

PCLK2 和 PA10 是本题 USART1 默认映射下的检查对象，不适用于任意串口：USART1 重映射后 RX 是 PB7；换成其他 USART/UART 时，还需按实际实例核对总线时钟和引脚。结合板卡与转接器确认兼容电平、共地、接收线和帧格式，并区分波特率偏差、错误标志与软件处理错误，不能只凭“乱码”锁定某一个原因。依据：[ST RM0008 Rev21，9.3.8、9.4.2、27.3.4 与第27章](https://www.st.com/resource/en/reference_manual/cd00171190.pdf)。尚未测量波形或在实物上复现，仍待用户审阅。

## uart2-048 | 故障排查：ORE 清除失败

标签：STM32F103, UART, 状态标志, 错误处理, 故障排查
难度：进阶

### 题目

程序试图使用 `USART_ClearFlag()` 清除 ORE，但错误标志仍然存在。

请解释原因，并说明正确的处理思路。

---

### 参考答案

`USART_ClearFlag()` 只支持 SPL 允许软件直接清除的特定标志，不能用它替代所有 USART 状态标志的硬件清除规则。

对于 STM32F103 的 ORE，应按照参考手册规定执行先读 SR、再读 DR 的操作。

还应检查：

- 实际错误是否仍然持续发生。
- 是否确实执行了规定的清除序列。
- 是否在清除后又产生了新的错误。
- 软件是否正确区分了标志清除和数据恢复。

清除标志只是恢复流程的一部分，不代表丢失的数据可以恢复。
