## 二、判断题

请判断正误，并说明理由。

### 第 16 题

USART1 的寄存器绝对地址等于 USART1 基地址加寄存器偏移地址。

### 第 17 题

在 STM32F103 中，USART1 使用 PCLK2，而 USART2、USART3 使用 PCLK1。

### 第 18 题

在普通 8N1 配置中，只要将 BRR 设置正确，即使 UE=0，也能够正常完成 USART 通信。

### 第 19 题

TXE=1 就意味着最后一个停止位已经从 TX 引脚发送完毕。

### 第 20 题

TC=1 时，表示发送数据寄存器与移位寄存器均为空，最后一帧已经发送完成。

### 第 21 题

RXNE=1 表示 RX 引脚当前一定处于低电平。

### 第 22 题

`USART_SendData()` 的作用是将待发送数据写入数据寄存器，它本身不负责等待 TXE。

### 第 23 题

`USART_ReceiveData()` 本身会等待 RXNE 置位，因此可以不检查接收状态就安全调用。

### 第 24 题

在 STM32F103 中，清除 ORE 时，按照手册规定执行读取 SR、再读取 DR 的操作。

### 第 25 题

`volatile` 能够保证寄存器读—改—写操作具有原子性。

### 第 26 题

使能 USART 的 RXNE 中断源后，就不需要配置 NVIC，也不需要编写中断服务程序。

### 第 27 题

使能 USART 的接收 DMA 请求后，仍然需要正确配置 DMA 控制器。

## 二、判断题答案

### 第 16 题：正确

寄存器绝对地址由外设基地址与寄存器偏移地址相加得到。

### 第 17 题：正确

STM32F103 中，USART1 位于 APB2，USART2、USART3 位于 APB1。

### 第 18 题：错误

UE=0 时 USART 整体未使能，单独配置 BRR 不足以完成正常通信。

### 第 19 题：错误

TXE 只表示发送数据寄存器为空，数据可能仍在移位寄存器中发送。

### 第 20 题：正确

### 第 21 题：错误

RXNE 表示接收数据寄存器非空，与 RX 引脚当前的高低电平不是同一个概念。

### 第 22 题：正确

`USART_SendData()` 负责写入 DR，本身不替调用者等待 TXE。调用者必须确保写入时机正确。

### 第 23 题：错误

`USART_ReceiveData()` 读取 DR，但不会自动等待 RXNE。调用者需要先确认数据已经准备好。

### 第 24 题：正确

### 第 25 题：错误

### 第 26 题：错误

## 三、简答题参考答案

### 第 28 题：寄存器地址计算

| 寄存器 | 偏移地址 | 绝对地址       |
| --- | ---- | ---------- |
| SR  | 0x00 | 0x40013800 |
| DR  | 0x04 | 0x40013804 |
| BRR | 0x08 | 0x40013808 |
| CR1 | 0x0C | 0x4001380C |
| CR2 | 0x10 | 0x40013810 |
| CR3 | 0x14 | 0x40013814 |

偏移地址只表示寄存器相对于外设基地址的位置，不能单独确定它在 MCU 地址空间中的绝对位置。

### 第 29 题：BRR 波特率计算

计算公式：

`USARTDIV = fCK / (16 × baud)`

代入：

`USARTDIV = 72000000 / (16 × 115200)`

得到：

`USARTDIV = 39.0625`

整数部分为 39，即 `0x27`。

小数部分为 0.0625：

`0.0625 × 16 = 1`

因此：

`BRR = (39 << 4) | 1 = 0x0271`

### 第 30 题：CR1 解析

`CR1 = 0x200C`

二进制置位情况：

- bit 13（UE）= 1。
- bit 3（TE）= 1。
- bit 2（RE）= 1。
- bit 12（M）= 0。
- bit 10（PCE）= 0。
- bit 9（PS）= 0。
- bit 5（RXNEIE）= 0。

因此，该配置启用了 USART、发送器和接收器，没有启用奇偶校验，也没有启用 RXNE 中断源，符合普通 8N1 收发的 CR1 配置要求。

### 第 31 题：CR2 停止位解析

| STOP | 含义       |
| ---- | -------- |
| 00   | 1 个停止位   |
| 01   | 0.5 个停止位 |
| 10   | 2 个停止位   |
| 11   | 1.5 个停止位 |

STOP 是多位字段。直接覆盖整个 CR2 可能破坏其他控制位。

修改字段时，应先清除 STOP 对应的位，再设置目标值，同时保留其他需要保留的位。

### 第 32 题：SR 状态标志解析

已知：

`SR = 0x00A0`

TXE 掩码：

`1 << 7 = 0x0080`

`0x00A0 & 0x0080 = 0x0080`

因此 TXE=1。

TC 掩码：

`1 << 6 = 0x0040`

`0x00A0 & 0x0040 = 0`

因此 TC=0。

RXNE 掩码：

`1 << 5 = 0x0020`

`0x00A0 & 0x0020 = 0x0020`

因此 RXNE=1。

最终结果：TXE=1、TC=0、RXNE=1。

### 第 33 题：库函数底层原理

| 函数                    | 主要作用                 | 是否自动等待状态标志 |
| --------------------- | -------------------- | ---------- |
| USART_Init()          | 根据结构体配置 USART 通信参数   | 否          |
| USART_Cmd()           | 控制 USART 整体使能        | 否          |
| USART_SendData()      | 写入发送数据寄存器            | 否          |
| USART_ReceiveData()   | 读取接收数据寄存器            | 否          |
| USART_GetFlagStatus() | 查询指定状态标志             | 否，只查询      |
| USART_ITConfig()      | 配置 USART 内部中断使能位     | 否          |
| USART_DMACmd()        | 使能或关闭 USART 的 DMA 请求 | 否          |

调用者必须理解每个函数的职责，并负责协调状态检查、数据处理和外设时序。

### 第 34 题：状态标志清除

| 标志   | 含义           | 清除方式                               |
| ---- | ------------ | ---------------------------------- |
| TXE  | 发送数据寄存器为空    | 写入 DR 后由硬件清除                       |
| TC   | 发送完成         | 按手册规定的方式清除，例如读取 SR 后写 DR，或向 TC 写 0 |
| RXNE | 接收数据寄存器非空    | 通常读取 DR 清除                         |
| IDLE | 接收线路空闲事件     | 先读 SR，再读 DR                        |
| ORE  | 接收溢出错误       | 先读 SR，再读 DR                        |
| FE   | 帧错误          | 先读 SR，再读 DR                        |
| NE   | 噪声错误         | 先读 SR，再读 DR                        |
| CTS  | CTS 状态变化     | 向对应标志写 0                           |
| LBD  | LIN Break 检测 | 向对应标志写 0                           |

不能把所有标志统一交给 `USART_ClearFlag()`，因为不同标志具有不同的硬件清除语义。STM32F1 SPL 的该函数只允许清除特定标志；错误标志和 IDLE 等必须遵循手册规定的读取序列。

### 第 35 题：初始化流程

合理流程：

1. 根据实际时钟树使能 GPIOA、USART1 所需的 RCC 时钟。
2. 配置 PA9 为复用推挽输出，PA10 为合适的输入模式。
3. 如使用重映射，配置 AFIO。
4. 配置 BRR，确定波特率。
5. 配置 CR1，确定字长、校验、收发使能和中断需求。
6. 配置 CR2，确定停止位及特殊模式。
7. 配置 CR3，确定流控、DMA 或其他高级功能。
8. 使能 USART。
9. 根据需要配置 NVIC 或 DMA 控制器。
10. 通过状态标志和实际通信验证配置。

各模块职责：

- RCC：提供外设时钟。
- GPIO：配置引脚模式。
- BRR：设置波特率分频。
- CR1：设置核心通信参数和收发控制。
- CR2：设置停止位及特殊模式。
- CR3：设置 DMA、硬件流控等高级功能。

### 第 36 题：发送时序

1. 软件确认 TXE=1。
2. 软件向 DR 写入数据。
3. TXE 清零。
4. 硬件将数据转移到发送移位寄存器。
5. TXE 重新置位，允许写入下一份数据。
6. 移位寄存器按照串行帧格式发送数据。
7. 最后一帧发送完成且发送数据寄存器为空时，TC 置位。

TXE 关注发送数据寄存器是否可用；TC 关注整个发送过程是否完成。因此 TXE 可以早于 TC 置位。

### 第 37 题：接收时序

1. USART 检测 RX 引脚上的起始位。
2. 硬件按配置的波特率采样数据。
3. 硬件完成数据帧接收。
4. 接收数据进入 DR，RXNE 置位。
5. 软件检查 RXNE 后读取 DR。
6. 正常读取后 RXNE 清除。

如果旧数据没有及时读取，而新数据又完成接收，可能产生 ORE。软件应及时取走数据，并按手册规定处理错误标志。

### 第 38 题：寄存器与库函数

应用程序调用 SPL 函数，SPL 函数访问 CMSIS 定义的寄存器，CPU 再通过总线访问 USART 外设，最终由硬件完成相应操作。

只记住函数名称，无法解释：

- 函数实际修改了哪些寄存器。
- 为什么需要等待 TXE 或 RXNE。
- 为什么某些状态标志需要特殊清除顺序。
- 初始化参数如何转化为寄存器配置。
- 硬件异常发生时应该检查什么。

第二层要求能够从寄存器与手册出发解释硬件行为。

## 四、寄存器与计算综合题参考答案

### 第 39 题：CR1 掩码计算

| 位            | 掩码     |
| ------------ | ------ |
| UE：bit 13    | 0x2000 |
| TE：bit 3     | 0x0008 |
| RE：bit 2     | 0x0004 |
| RXNEIE：bit 5 | 0x0020 |
| TXEIE：bit 7  | 0x0080 |
| TCIE：bit 6   | 0x0040 |

只启用 UE、TE、RE：

`0x2000 | 0x0008 | 0x0004 = 0x200C`

### 第 40 题：寄存器读—改—写

目标字段为 bit 5:4。

字段掩码：

`MASK = 0b00110000 = 0x30`

目标字段值为二进制 `10`，放入 bit 5:4 后：

`VALUE = 0b00100000 = 0x20`

常规读—改—写表达式：

`REG = (REG & ~MASK) | VALUE`

不能简单执行 `REG |= VALUE`，因为原字段中可能已有 1，按位或无法将原来的 1 清零。

普通读—改—写还可能存在并发修改、非原子操作，以及对具有读写副作用的寄存器产生意外影响等风险。

### 第 41 题：波特率变化

已知：

`fCK = 72000000`

`baud = 9600`

计算：

`USARTDIV = 72000000 / (16 × 9600) = 468.75`

整数部分：

`468 = 0x1D4`

小数部分：

`0.75 × 16 = 12 = 0xC`

因此：

`BRR = (468 << 4) | 12 = 0x1D4C`

波特率越低，在输入时钟不变的情况下，所需分频系数越大，因此 BRR 的数值随之变化。

### 第 42 题：初始化目标值

在题设条件下：

| 寄存器 | 目标值    |
| --- | ------ |
| BRR | 0x0271 |
| CR1 | 0x200C |
| CR2 | 0x0000 |
| CR3 | 0x0000 |

这些值仅表示题设中 USART 通信参数的目标配置。

它们不能代替 RCC 时钟使能、GPIO 引脚配置、AFIO 映射确认、实际接线以及其他必要的系统配置。

## 五、故障分析题参考答案

### 第 43 题：TX 无输出

建议按层次检查：

1. **RCC：** GPIOA、USART1 时钟是否使能。
2. **GPIO：** PA9 是否配置为复用推挽输出。
3. **AFIO：** USART1 是否采用默认映射，是否存在重映射配置不一致。
4. **USART：** UE、TE 是否置位，初始化是否正确。
5. **BRR 与帧格式：** 是否使用正确的 PCLK2，波特率和数据帧参数是否匹配。
6. **物理连接：** STM32 TX 是否连接到 USB 转 TTL 的 RX，双方是否共地。
7. **软件流程：** 程序是否实际执行到发送逻辑，TXE 是否正常变化。

### 第 44 题：TXE 正常但 TC 不置位

TXE=1 只能证明发送数据寄存器当前为空，可以接受新数据；它不能单独证明最后一帧已经发送完成。

应检查：

- 是否确实写入了数据。
- USART 是否使能。
- 是否持续写入数据，导致发送通路没有完全空闲。
- TC 的观察时机是否正确。
- 是否存在对 TC 的清除操作。
- 是否正确区分了软件调试观察与硬件真实状态。

### 第 45 题：接收出现 ORE

ORE 可能在旧接收数据尚未被读取，而新数据又完成接收时产生。

扩大软件数组容量只能缓解软件缓冲区空间不足，不能直接解决 USART 硬件接收数据未及时读取的问题。

正确思路：

1. 及时读取 DR。
2. 检查程序是否长时间阻塞。
3. 检查接收处理是否及时。
4. 必要时考虑中断或 DMA。
5. 区分硬件 ORE 与软件数组溢出。
6. 按手册规定清除错误标志，并恢复接收流程。

清除 ORE 不能恢复已经丢失的数据。

### 第 46 题：中断没有进入

应检查：

1. USART1 时钟是否使能。
2. GPIO 与实际接线是否正确。
3. USART 接收功能 RE 是否启用。
4. RXNE 是否确实置位。
5. RXNE 中断源是否使能。
6. NVIC 对应的 USART1 中断通道是否使能。
7. 中断服务函数名称是否正确。
8. 中断处理文件是否参与编译与链接。
9. 是否存在全局中断关闭等影响因素。
10. 是否有其他代码提前读取 DR，导致 RXNE 被清除。

### 第 47 题：接收数据乱码

- **时钟：** 确认实际 PCLK2。
- **BRR：** 根据实际输入时钟重新计算波特率。
- **帧格式：** 检查数据位、校验位和停止位。
- **GPIO：** 检查 PA10 的输入模式与 USART1 映射。
- **物理连接：** 检查 TX/RX 交叉连接、共地及信号电平。
- **接收逻辑：** 检查读取 DR 的时机、数据类型、缓冲区索引和数据处理过程。

### 第 48 题：清除标志失败

`USART_ClearFlag()` 只支持 SPL 允许软件直接清除的特定标志，不能用它替代所有 USART 状态标志的硬件清除规则。

对于 STM32F103 的 ORE，应按照参考手册规定执行先读 SR、再读 DR 的操作。

还应检查：

- 实际错误是否仍然持续发生。
- 是否确实执行了规定的清除序列。
- 是否在清除后又产生了新的错误。
- 软件是否正确区分了标志清除和数据恢复。

清除标志只是恢复流程的一部分，不代表丢失的数据可以恢复。

# 第三部分：第二层理论验收标准

建议按以下标准检查掌握程度：

| 考核项目  | 建议标准                 |
| ----- | -------------------- |
| 选择题   | 至少 13/15 正确          |
| 判断题   | 至少 10/12 正确          |
| 简答题   | 能解释关键寄存器与硬件行为        |
| 寄存器计算 | 能独立计算地址、掩码与 BRR      |
| 故障分析  | 能按时钟、引脚、寄存器、软件逻辑逐层定位 |

特别注意：

1. 能背出 BRR 的值，不等于能够独立计算波特率。
2. 能说出 TXE、TC、RXNE 的含义，不等于理解它们对应的硬件时序。
3. 能调用 SPL 函数，不等于理解其底层寄存器操作。
4. 能清除错误标志，不等于能够恢复已经丢失的数据。

**第二层最终目标：能够结合 STM32F103 参考手册，从寄存器和硬件行为出发解释 USART 的初始化、发送、接收与错误处理。**
