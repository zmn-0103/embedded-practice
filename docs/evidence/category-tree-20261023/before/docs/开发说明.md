## 安装与启动

在仓库根目录执行：

```powershell
npm ci
npm run dev
```

首次准备开发环境需要下载依赖和 Electron。`postinstall` 使用 electron-builder 重建原生依赖；失败时应解决版本或环境问题，不使用占位数据库绕过。安装后的应用携带 Electron 运行时，核心运行不需要下载开发依赖。

`npm run dev` 启动真实开发服务器与桌面窗口。`npm start` 运行已有 `out/` 产物，需先构建。

## 检查与测试

```powershell
npm run check
npm test
npm run test:desktop
```

- `check`：主进程、预加载、配置、测试与界面类型检查，以及源码/配置格式检查；不格式化用户原始计划书。
- `test`：范围固定为根目录 `tests/unit/**/*.test.ts`，恢复副本不计入。最近封存的 M4 第三批报告为 28 文件、561 项，含备份恢复与数据位置边界；历史 503 项为会话筛选修复时结果，不是本批新运行。
- `test:desktop`：先构建，再以开发 Electron 执行；最近封存 M4 第三批开发/解包各150项，包含既有101项及后续备份恢复/数据位置场景。使用生产构建页面，区别于 `npm run dev` 热更新检查。数据库帮助器位于 `tests/integration/`，由 Electron 流程调用，不增加生产窗口测试入口；本批 M5 脚本结果另记。
- 原生 SQLite 按 Electron ABI 重建后，不能假定系统 Node 能直接加载同一个二进制。因此实际业务数据库事务在 Electron 中执行；Node 内置 SQLite 用于创建/只读核对独立测试夹具与备份。
- 测试为每个场景创建独立临时目录，完成后只清理经父目录与前缀检查的测试目录。

M1 第一批纯解析入口为 `src/main/services/library/parse-question-bank.ts`，不读取文件或数据库。第二批入口 `src/main/services/library/prepare-import.ts` 接收一个或多个 `.md` 绝对路径，读取并校验 Markdown 与真实图片，返回完整批次快照或首个失败文件的错误。第三批 `src/main/services/library/import-preparation.ts` 将准备操作放入 Node 工作线程，通过 `prepare(paths, signal?)` / `close()` 管理生命周期；服务需要内部诊断回调，默认期限 120 秒。

第四批内部入口 `await openLibraryImportService(databasePath, reportError)` 组合预览和数据库服务，构建为 `out/main/library-import.js`。`preview(paths, signal?)` 返回令牌/摘要；`commit(token)` 同步事务提交私有快照；`discard(token)` 释放预览；`close()` 等待准备线程并关闭连接。第五批增加固定的列表、题干、答案与图片读取方法，并由主入口创建服务、传入本地诊断函数，经白名单 IPC 调用。准备仍通过 `out/main/import-preparation.js` 与固定工作入口在线程执行，详见[预览与提交](architecture/M1预览与提交.md)和[窗口与受控内容](architecture/M1窗口与受控内容.md)。

M2 第一批入口 `await openPracticeService(databasePath, reportError)` 构建为 `out/main/practice.js`，第二批已由主入口创建独立服务并接白名单 IPC/窗口。固定 `read/start/saveDraft/reveal/rateAndAdvance/navigate/end/close` 方法；输入 Schema、游标/请求幂等和独立连接均在内部边界处理。响应回执不代表最新位置，调用后单独读取当前视图。草稿最大 1MiB UTF-8，超限拒绝不截断；控制器保留页面输入、修订和结果未明的原请求，500ms 保存并在离开前刷新。详见[顺序练习与保存](architecture/M2顺序练习与保存.md)和[练习窗口](architecture/M2练习窗口与保存.md)。

## 数据与诊断

| 运行形态 | 默认数据目录 |
|---|---|
| 安装版 | `%APPDATA%/embedded-practice/` |
| 开发与预览 | `%APPDATA%/embedded-practice-dev/` |

数据库为 `practice.sqlite3`，Chromium 会话文件放在 `session/`，错误堆栈写入 `logs/application.log`。界面只显示中文错误说明。数据库结构为 6，保存启动、题库/版本/图片、独立题目状态、导入回执、练习会话/作答行/请求回执与单行显示设置；会话模式允许顺序和随机，filters_json 保存规范化的创建条件；旧会话为 NULL，读取返回 filters:null 明确未知。正常退出先由 UUID/10 秒超时握手确认页面最新输入及已发出的显示设置保存；无法确认时默认返回窗口，只有明确放弃才继续退出。随后关闭练习连接并协调题库线程/其他连接，重复关闭共用协调。强制结束仅恢复已确认保存内容。

数据库损坏、无应用标识却非空、应用标识不符或结构版本不受支持时停止使用并保留文件，不自动修复或清空。已知 v1～v6 库先一致性备份到数据目录 `backups/pre-migration-v<旧版本>-UUID.sqlite3` 并校验，再事务迁移到 7；备份失败停止，DDL 或外键失败回滚。v3 替换会话表 CHECK，保留全部会话字段与队列/作答/回执，并拒绝未知会话索引/触发器，详见[随机练习与模式升级](architecture/M3随机练习与模式升级.md)。v4 追加显示设置后与 v5 一样增补会话筛选列；v5 不重建会话，原条件未知保留 NULL；所有旧库最后追加 palette 四值列，v6 仅执行这一增量。旧 M5 程序/候选 NSIS、旧 M0 均不能打开结构 7。新 UI 完整程序在 `release/ui-20261023/win-unpacked/`；M5 历史候选仍对应旧界面结构 6，不能用它验收新配色。迁移保护与完整备份恢复已接通，安装/升级仍待验，不通过删除正式数据库掩盖启动失败。
