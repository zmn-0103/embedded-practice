## uart2-029 | BRR 波特率计算

标签：UART, 第二层, 试用选集

### 题目

已知：

- USART1 输入时钟：72 MHz
- 目标波特率：115200 baud
- 过采样倍数：16

请计算：

1. USARTDIV
2. 整数部分
3. 小数部分
4. BRR 的最终值

写出计算过程。

### 参考答案

计算公式：

`USARTDIV = fCK / (16 × baud)`

代入：

`USARTDIV = 72000000 / (16 × 115200)`

得到：

`USARTDIV = 39.0625`

整数部分为 39，即 `0x27`。

小数部分为 0.0625：

`0.0625 × 16 = 1`

因此：

`BRR = (39 << 4) | 1 = 0x0271`

## uart2-030 | CR1 解析

标签：UART, 第二层, 试用选集

### 题目

已知：

`CR1 = 0x200C`

请分析：

1. UE、TE、RE 分别是什么状态？
2. M、PCE、PS 是什么状态？
3. 是否启用了 RXNE 中断？
4. 该配置是否符合普通 8N1 收发的 CR1 要求？

### 参考答案

`CR1 = 0x200C`

二进制置位情况：

- bit 13（UE）= 1。
- bit 3（TE）= 1。
- bit 2（RE）= 1。
- bit 12（M）= 0。
- bit 10（PCE）= 0。
- bit 9（PS）= 0。
- bit 5（RXNEIE）= 0。

因此，该配置启用了 USART、发送器和接收器，没有启用奇偶校验，也没有启用 RXNE 中断源，符合普通 8N1 收发的 CR1 配置要求。

## uart2-031 | CR2 停止位解析

标签：UART, 第二层, 试用选集

### 题目

CR2 的 STOP 字段位于 bit 13:12。

请回答：

1. STOP=`00` 表示什么？
2. STOP=`01` 表示什么？
3. STOP=`10` 表示什么？
4. 如果只修改 STOP 字段，为什么不能直接用新字段值覆盖整个 CR2？

### 参考答案

| STOP | 含义       |
| ---- | -------- |
| 00   | 1 个停止位   |
| 01   | 0.5 个停止位 |
| 10   | 2 个停止位   |
| 11   | 1.5 个停止位 |

STOP 是多位字段。直接覆盖整个 CR2 可能破坏其他控制位。

修改字段时，应先清除 STOP 对应的位，再设置目标值，同时保留其他需要保留的位。

## uart2-032 | SR 状态标志解析

标签：UART, 第二层, 试用选集

### 题目

已知：

`SR = 0x00A0`

请判断：

1. TXE 是否置位？
2. TC 是否置位？
3. RXNE 是否置位？

写出对应的掩码判断过程。

### 参考答案

已知：

`SR = 0x00A0`

TXE 掩码：

`1 << 7 = 0x0080`

`0x00A0 & 0x0080 = 0x0080`

因此 TXE=1。

TC 掩码：

`1 << 6 = 0x0040`

`0x00A0 & 0x0040 = 0`

因此 TC=0。

RXNE 掩码：

`1 << 5 = 0x0020`

`0x00A0 & 0x0020 = 0x0020`

因此 RXNE=1。

最终结果：TXE=1、TC=0、RXNE=1。

## uart2-034 | 状态标志清除

标签：UART, 第二层, 试用选集

### 题目

请说明以下标志的含义与清除方式：

1. TXE
2. TC
3. RXNE
4. IDLE
5. ORE
6. FE
7. NE
8. CTS
9. LBD

特别说明：为什么不能把所有标志都统一交给 `USART_ClearFlag()` 处理？

### 参考答案

| 标志   | 含义           | 清除方式                               |
| ---- | ------------ | ---------------------------------- |
| TXE  | 发送数据寄存器为空    | 写入 DR 后由硬件清除                       |
| TC   | 发送完成         | 按手册规定的方式清除，例如读取 SR 后写 DR，或向 TC 写 0 |
| RXNE | 接收数据寄存器非空    | 通常读取 DR 清除                         |
| IDLE | 接收线路空闲事件     | 先读 SR，再读 DR                        |
| ORE  | 接收溢出错误       | 先读 SR，再读 DR                        |
| FE   | 帧错误          | 先读 SR，再读 DR                        |
| NE   | 噪声错误         | 先读 SR，再读 DR                        |
| CTS  | CTS 状态变化     | 向对应标志写 0                           |
| LBD  | LIN Break 检测 | 向对应标志写 0                           |

不能把所有标志统一交给 `USART_ClearFlag()`，因为不同标志具有不同的硬件清除语义。STM32F1 SPL 的该函数只允许清除特定标志；错误标志和 IDLE 等必须遵循手册规定的读取序列。

## uart2-035 | 初始化流程

标签：UART, 第二层, 试用选集

### 题目

请从硬件依赖关系出发，写出 USART1 默认映射下的主要初始化步骤，并说明 RCC、GPIO、BRR、CR1、CR2、CR3 分别负责什么。

### 参考答案

合理流程：

1. 根据实际时钟树使能 GPIOA、USART1 所需的 RCC 时钟。
2. 配置 PA9 为复用推挽输出，PA10 为合适的输入模式。
3. 如使用重映射，配置 AFIO。
4. 配置 BRR，确定波特率。
5. 配置 CR1，确定字长、校验、收发使能和中断需求。
6. 配置 CR2，确定停止位及特殊模式。
7. 配置 CR3，确定流控、DMA 或其他高级功能。
8. 使能 USART。
9. 根据需要配置 NVIC 或 DMA 控制器。
10. 通过状态标志和实际通信验证配置。

各模块职责：

- RCC：提供外设时钟。
- GPIO：配置引脚模式。
- BRR：设置波特率分频。
- CR1：设置核心通信参数和收发控制。
- CR2：设置停止位及特殊模式。
- CR3：设置 DMA、硬件流控等高级功能。

## uart2-036 | 发送时序

标签：UART, 第二层, 试用选集

### 题目

请按照硬件执行顺序，描述软件发送一个字节时，从写入 DR 到 TC 置位的主要过程。

解释 TXE 为什么可能早于 TC 置位。

### 参考答案

1. 软件确认 TXE=1。
2. 软件向 DR 写入数据。
3. TXE 清零。
4. 硬件将数据转移到发送移位寄存器。
5. TXE 重新置位，允许写入下一份数据。
6. 移位寄存器按照串行帧格式发送数据。
7. 最后一帧发送完成且发送数据寄存器为空时，TC 置位。

TXE 关注发送数据寄存器是否可用；TC 关注整个发送过程是否完成。因此 TXE 可以早于 TC 置位。

## uart2-037 | 接收时序

标签：UART, 第二层, 试用选集

### 题目

请描述一个字节从 RX 引脚进入 USART，到软件读取 DR 的主要过程。

说明 RXNE 的产生条件、读取 DR 的作用，以及 ORE 可能如何产生。

### 参考答案

1. USART 检测 RX 引脚上的起始位。
2. 硬件按配置的波特率采样数据。
3. 硬件完成数据帧接收。
4. 接收数据进入 DR，RXNE 置位。
5. 软件检查 RXNE 后读取 DR。
6. 正常读取后 RXNE 清除。

如果旧数据没有及时读取，而新数据又完成接收，可能产生 ORE。软件应及时取走数据，并按手册规定处理错误标志。

## uart2-040 | 寄存器读—改—写

标签：UART, 第二层, 试用选集

### 题目

假设某寄存器中的目标字段位于 bit 5:4，现在需要将该字段设置为二进制 `10`。

请说明：

1. 目标字段掩码是多少？
2. 应先清除哪些位？
3. 为什么不能简单地对寄存器执行 `REG |= VALUE`？
4. 普通读—改—写操作有哪些潜在风险？

### 参考答案

目标字段为 bit 5:4。

字段掩码：

`MASK = 0b00110000 = 0x30`

目标字段值为二进制 `10`，放入 bit 5:4 后：

`VALUE = 0b00100000 = 0x20`

常规读—改—写表达式：

`REG = (REG & ~MASK) | VALUE`

不能简单执行 `REG |= VALUE`，因为原字段中可能已有 1，按位或无法将原来的 1 清零。

普通读—改—写还可能存在并发修改、非原子操作，以及对具有读写副作用的寄存器产生意外影响等风险。

## uart2-041 | 波特率变化

标签：UART, 第二层, 试用选集

### 题目

假设 USART1 输入时钟仍为 72 MHz，但目标波特率改为 9600 baud。

请计算：

1. USARTDIV
2. BRR 的整数部分
3. BRR 的小数部分
4. 最终 BRR 值

说明与 115200 baud 相比，BRR 为什么发生变化。

### 参考答案

已知：

`fCK = 72000000`

`baud = 9600`

计算：

`USARTDIV = 72000000 / (16 × 9600) = 468.75`

整数部分：

`468 = 0x1D4`

小数部分：

`0.75 × 16 = 12 = 0xC`

因此：

`BRR = (468 << 4) | 12 = 0x1D4C`

波特率越低，在输入时钟不变的情况下，所需分频系数越大，因此 BRR 的数值随之变化。

## uart2-043 | TX 无输出

标签：UART, 第二层, 试用选集

### 题目

USART1 初始化后，程序已经执行发送函数，但电脑收不到任何字符。

1. RCC

4. USART 控制寄存器

### 参考答案

## uart2-044 | TXE 正常但 TC 不置位

标签：UART, 第二层, 试用选集

### 题目

程序发现 TXE 已置位，但一直无法观察到预期的 TC 状态。

请说明：

1. TXE 置位能够证明什么？
2. 为什么它不能证明最后一帧发送完成？
3. 应重点检查哪些因素？

### 参考答案

TXE=1 只能证明发送数据寄存器当前为空，可以接受新数据；它不能单独证明最后一帧已经发送完成。

应检查：

- 是否确实写入了数据。
- USART 是否使能。
- 是否持续写入数据，导致发送通路没有完全空闲。
- TC 的观察时机是否正确。
- 是否存在对 TC 的清除操作。
- 是否正确区分了软件调试观察与硬件真实状态。

## uart2-045 | 接收出现 ORE

标签：UART, 第二层, 试用选集

### 题目

USART1 连续接收数据时出现 ORE。

请分析：

1. ORE 的产生条件。
2. 为什么扩大软件数组容量不一定解决问题？
3. 应如何处理硬件标志与软件缓冲区？
4. 清除错误标志后，是否能够恢复已经丢失的数据？

### 参考答案

ORE 可能在旧接收数据尚未被读取，而新数据又完成接收时产生。

扩大软件数组容量只能缓解软件缓冲区空间不足，不能直接解决 USART 硬件接收数据未及时读取的问题。

正确思路：

1. 及时读取 DR。
2. 检查程序是否长时间阻塞。
3. 检查接收处理是否及时。
4. 必要时考虑中断或 DMA。
5. 区分硬件 ORE 与软件数组溢出。
6. 按手册规定清除错误标志，并恢复接收流程。

清除 ORE 不能恢复已经丢失的数据。

## uart2-046 | 中断没有进入

标签：UART, 第二层, 试用选集

### 题目

程序已经执行：

`USART_ITConfig(USART1, USART_IT_RXNE, ENABLE)`

但接收字符时没有进入中断服务程序。

请列出至少五项需要检查的内容。

### 参考答案

应检查：

1. USART1 时钟是否使能。
2. GPIO 与实际接线是否正确。
3. USART 接收功能 RE 是否启用。
4. RXNE 是否确实置位。
5. RXNE 中断源是否使能。
6. NVIC 对应的 USART1 中断通道是否使能。
7. 中断服务函数名称是否正确。
8. 中断处理文件是否参与编译与链接。
9. 是否存在全局中断关闭等影响因素。
10. 是否有其他代码提前读取 DR，导致 RXNE 被清除。

## uart2-047 | 接收数据乱码

标签：UART, 第二层, 试用选集

### 题目

电脑发送字符后，STM32 观察到的数据不符合预期。

请从时钟、BRR、数据帧格式、GPIO、物理连接和接收逻辑六个方面分析可能原因。

### 参考答案

- **时钟：** 确认实际 PCLK2。
- **BRR：** 根据实际输入时钟重新计算波特率。
- **帧格式：** 检查数据位、校验位和停止位。
- **GPIO：** 检查 PA10 的输入模式与 USART1 映射。
- **物理连接：** 检查 TX/RX 交叉连接、共地及信号电平。
- **接收逻辑：** 检查读取 DR 的时机、数据类型、缓冲区索引和数据处理过程。

## uart2-048 | 清除标志失败

标签：UART, 第二层, 试用选集

### 题目

程序试图使用 `USART_ClearFlag()` 清除 ORE，但错误标志仍然存在。

请解释原因，并说明正确的处理思路。

---

### 参考答案

`USART_ClearFlag()` 只支持 SPL 允许软件直接清除的特定标志，不能用它替代所有 USART 状态标志的硬件清除规则。

对于 STM32F103 的 ORE，应按照参考手册规定执行先读 SR、再读 DR 的操作。

还应检查：

- 实际错误是否仍然持续发生。
- 是否确实执行了规定的清除序列。
- 是否在清除后又产生了新的错误。
- 软件是否正确区分了标志清除和数据恢复。

清除标志只是恢复流程的一部分，不代表丢失的数据可以恢复。
