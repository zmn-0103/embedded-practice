# M4 完整备份与恢复预览

日期：2026-10-22。本文记录 M4 第一批的导出与只读预览实现，以下“本批”均指第一批。第二批已经增加有凭据预览、保护性备份、实际替换/回退与重启，当前链路见[M4 恢复执行](M4恢复执行与回退.md)。正式数据库结构仍为 6，窗口没有任意文件或 SQL 接口。

## 导出

`SettingsPane → BackupPanel → preload → registerBackupIpc → openBackupService.export`。显示设置请求处理中禁用备份，备份期间禁用显示保存和切页。练习通过原返回流程保存后才能进入设置。

备份服务单独持有当前库的只读连接，调用 SQLite 在线一致性 `backup`。目标目录先经真实路径规范化；运行数据目录及其目录链接、当前数据库和伴随文件硬链接、非普通目标、带 WAL/SHM/journal 的目标均拒绝。先在目标同卷 `mkdtemp` 目录生成副本，切到 DELETE 日志模式，在副本写入备份格式 1 的 `backup_manifest`（实际生成时间、应用版本、源结构版本），校验后关闭连接。发布前再次核对目标路径，最后 rename 发布；失败不预先删除或截断已有目标。清理只作用于服务自己创建的暂存目录。

导出保持全部源业务表不变，不重新拼装题库或重算历史；额外自定义表也随数据库完整保留。已有同名 manifest 只有明确符合已知五列结构及格式 1 时才允许更新，未知命名冲突停止导出。新加 manifest 只存在于备份副本，当前数据库不增加表或升级结构。备份进行中其他连接提交事务时由 SQLite 一致性备份保证一个完整快照；备份覆盖的是完成时得到的已提交状态，不承诺未提交的按键或未保存表单选择。实际并发检查比较所有业务表，要求完整等于事务前或事务后状态。

manifest 的 app_version 来自实际进程 `app.getVersion()`；开发检查直接启动 JS 时该值为 Electron 42.11.15，打包应用为 0.1.0，测试与本次进程精确核对。数据兼容依据 application_id、user_version 和实际结构/内容校验，不凭应用版本号推断。

## 预览

系统选择单个文件后，经普通文件/真实路径/当前数据别名/数据库伴随文件检查。复制前后复核来源文件设备、inode、大小、修改与变更时间，以及选择路径的真实目标，读取中变化时失败。这里复制的是用户选择的独立备份文件，不是正在使用的运行数据库。

副本位于当前数据目录 `backup-staging/preview-<随机值>/`。先只读检查应用标识、受支持结构、完整性、外键与备份元数据。源结构 1～5 时，只对暂存副本调用原迁移流程，保留其备份及回滚规则；原文件和当前库均不迁移。随后核查所有业务表和列、显示设置、完整筛选对象、版本正文/定义/图片绑定及资源字节 SHA-256，再读取数量摘要。成功或失败均关闭副本并清理自建目录。没有时间元数据的历史备份显示未知，不冒充精确导出时间。

`integrity_check` 与外键检查、业务 JSON 和图片哈希各自检查不同边界；本批没有宣称验证所有像素解码、正式题目技术正确性或大数据性能。摘要不返回题干、参考答案、历史作答或草稿正文。

## 生命周期与失败

IPC 和服务各有单任务保护。选择期间导航、渲染进程丢失或关闭使选择失效；晚到路径不能开始写入。执行中的导出或预览必须完成收尾，主进程在正常保存握手后等待备份 IPC 与服务，再关闭业务连接。正常退出不会中途关闭备份所需连接。意外失败日志使用固定描述，不序列化无效文件中的任意内容或 Zod 对象。

当前摘要是一次预览的结果，没有可执行恢复令牌。M4 第二批需重新设计暂存预览的保留/确认与防来源变化协议，并完成保护性备份、关闭所有连接、伴随文件处理、替换回退与重启；不能将本批预览摘要直接视作恢复已发生。

SQLite 一致性备份语义参考 [better-sqlite3 官方 API](https://github.com/WiseLibs/better-sqlite3/blob/master/docs/api.md#backupdestination-options---promise)，并与本地固定 12.11.1 实现及实际 Electron/解包检查共同核实。
