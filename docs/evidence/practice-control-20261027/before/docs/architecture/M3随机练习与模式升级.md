# M3 随机练习与模式升级

日期：2026-10-21。行为基线见[第二批行为与验收](../M3第二批行为与验收.md)，实际运行结果见[证据索引](../evidence/m3b/README.md)。本说明覆盖本批实现，不代表单题历史、更新待复习展示、主题字号或 M3 全部验收已完成。

## 输入到固定队列

1. `PracticeWorkspace` 在首页维护顺序／随机选择，默认顺序，与专题、数量、筛选一起捕获成 `StartPractice`。页面结果未确认时保存原请求并禁用选择，重试不生成新 UUID 或改变模式。
2. 现有 `practice:start` 白名单通道和服务再次使用 `startPracticeSchema` 校验。`mode` 只允许 `sequential`、`random`；省略时不在解析结果中补字段，保持旧 JSON 与回执哈希。仓储在局部使用顺序缺省。
3. `practice-repository.ts` 的同一 IMMEDIATE 事务先读取原请求回执。已有回执直接返回；相同 UUID 改模式或其他字段返回 `REQUEST_CONFLICT`，均不重新取样。
4. 新请求先校验旧活动轮及替换游标，再使用与题库相同的绑定参数筛选。顺序查询按原专题／题目顺序；随机查询对完整匹配集执行 `ORDER BY random(), q.id LIMIT @limit`。数量为全部时 LIMIT 为 -1，不足数量自然返回全部匹配题目。
5. 没有匹配题目时抛出 `NO_QUESTIONS`，不结束原轮。确定非空队列后，事务才结束旧轮、写入新轮模式和逐项内容版本，最后写入幂等回执；任一写失败整笔回滚。

`practice_items` 现有 `(session_id, question_id)` 唯一约束保证一轮内身份不重复。相同随机键使用题目数据库 ID 作为稳定的第二排序键。不同轮可重复出现相同题目和顺序，程序不强制新轮一定不同，也未做随机分布统计验收。

随机排序只发生在新轮建立时。`read`、继续、上一题、下一题、保存、重开及导入都不重新调用选题查询。读取摘要来自会话的实际模式，练习区域、进度和结果使用该模式；首页选择只决定下次开始，不能改变已存会话。

## 结构 4 与旧库保护

结构 3 的 `practice_sessions.mode` 只有 sequential CHECK；结构 4 接受两种模式，其他列与关系保持。

- 新库一次创建结构 4。
- 已知 v1／v2 继续在保护性备份后创建缺少的表，直接迁移到结构 4。
- v3 在 `backups/pre-migration-v3-UUID.sqlite3` 完成一致性备份后，核对备份完整性、应用 ID 与旧版本。备份期间标识或版本变化时停止。
- v3 的父表 CHECK 无法直接调整。按 [SQLite 官方修改表结构流程](https://www3.sqlite.org/lang_altertable.html)，事务外关闭当前连接的外键执行；事务内建固定新表、显式复制全部八个会话字段、删除旧会话表、将新表改回原名并重建单活动轮唯一索引，检查全库外键后才提交版本 4；finally 恢复外键执行。
- 队列、作答、用户状态、内容版本、图片及原幂等回执不重建。未知会话索引或触发器使升级停止，避免替换表时静默丢失；已有同名迁移表或其他 DDL 错误也使事务回滚。损坏外键不会通过升级被掩盖。

迁移成功后重开不再生成迁移备份。旧版程序不支持结构 4，不能与新库混用；使用当前完整 Windows 解包目录。这里是已知版本的自动升级保护，完整备份导出／恢复与通用迁移管理仍属于 M4。

## 验证边界

冻结旧结构夹具 `tests/fixtures/practice-v3-schema.ts` 与改前生产 SQL 在展开固定草稿限额后逐字符一致，来源核对单列于证据。迁移测试在真实 SQLite 中构造旧轮和旧回执，分别比较升级前备份与新库全部业务表，再实际继续旧顺序轮。

`random-practice-exercise.ts` 只在测试连接覆盖 SQLite random 函数，用可控排序证明完整候选集参与取样、同键仍无重复、重复请求不再调用 random；故障触发器验证中途写入失败及重试。真实窗口测试使用生产连接原生 random，并核对固定队列、真实作答、自评、版本、正常与强制结束后的独立进程恢复、更新归档及结果未确认后的原请求重试。

恢复验证分别保留输入原文、编辑后控件值、同环境原生 textarea 赋值值和 SQLite 快照：本环境 CRLF 经自动化编辑插入后保留，原生 value 赋值及重开显示为 LF；数据库仍须逐字保留 CRLF。原生赋值测量用于精确区分显示与持久化，不能据此推断所有剪贴板或输入法表现。[HTML 标准对 textarea API 值与换行的说明](https://html.spec.whatwg.org/multipage/form-control-infrastructure.html)作为参考，当前结果以本批实测为准。

所有测试使用独立临时目录与生成题库。文件选择为显式替身；真实 Windows DPI、完整输入法／外部剪贴板、正式题库人工审阅、安装升级和压力性能仍单列待验。
