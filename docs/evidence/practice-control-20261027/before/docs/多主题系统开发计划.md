# 嵌入式刷题本：可安装多主题系统与 Claude 风格主题开发计划

## 一、目标与实施基线

为嵌入式刷题本增加可扩展的主题系统：**用户可以安装多个本地主题包，预览、切换、更新和卸载主题；Claude Code Desktop 风格是其中一套主题。**

已通过网页版读完引用的《GitHub主题思路》完整正文。本计划吸收其中的工作区布局、侧栏、中央阅读区、辅助面板和设计令牌思路，并结合当前软件实现调整范围。

本轮仅提供计划，不生成文件、不修改代码、不运行迁移。后续实施以当前 V0.0.0、构建 `20261024.4-v000`、数据库结构 9 为起点。

已确定的产品选择：

- **安装方式：本地主题包导入**，保持离线使用，不建设在线主题商店。
- **主题范围：视觉与受控布局**，允许改变颜色、字体风格、圆角、间距、导航和面板呈现。
- 保留现有松间绿、晴空蓝、暖沙金、暮山紫四套主题，新增 Claude 风格主题。
- 明暗模式、正文字号仍由用户独立选择；每套主题均支持浅色、深色和跟随系统。
- 题库、草稿、固定练习队列、揭晓、自评、收藏、历史、分类及练习方案沿用现有规则。

## 二、用户功能与主题表现

### 1. 主题管理

在“设置与数据”中将现有配色选择扩展为主题管理区，提供：

| 功能 | 约定行为 |
|---|---|
| 查看主题 | 区分内置与已安装主题，显示名称、作者、版本、简述及当前使用状态 |
| 安装主题 | 选择本地主题文件，校验后展示预览和主题信息，确认安装后加入列表 |
| 预览主题 | 在独立预览区域展示导航、正文、代码块、按钮、输入框及辅助面板 |
| 应用主题 | 点击“保存并应用”后全局生效，无须重启；关闭重开后保留 |
| 更新主题 | 同一主题 ID 的新版本通过导入更新，显示版本变化并明确确认 |
| 卸载主题 | 仅允许卸载外部主题；当前主题卸载时提示并切换到内置松间绿 |
| 恢复默认 | 恢复内置松间绿、跟随系统和默认字号，不影响学习数据 |

安装与应用分开：安装成功不会自动改变当前外观。预览未保存时不影响其他页面；保存失败保留原主题和待保存选择。

同一 ID、同一版本且内容一致的重复导入视为已安装；同版本不同内容拒绝覆盖；第一版不提供降级安装。内置主题 ID 保留，外部包不能覆盖。

### 2. 两种受控布局

第一版由程序实现两种布局预设，主题包选择其中一种：

- **经典布局**：延续当前软件的导航和内容组织，供现有四套主题使用。
- **学习工作区布局**：左侧可折叠导航、中央阅读与作答区、右侧可隐藏的辅助面板，供 Claude 风格主题使用。

两种布局使用同一套业务组件和状态。主题切换只调整样式与布局参数，不通过卸载并重新创建练习组件实现。

学习工作区的具体行为：

- 左侧复用板块、开始练习、题库、学习记录、设置与数据等现有入口。
- 中央保留题干、作答区、参考答案及自评的原有顺序和显示条件。
- 练习操作栏在工作区底部保持可达，预留空间，避免遮挡内容。
- 右侧仅展示已有的题目属性、标签和本轮进度，不新增统计口径。
- 窄窗口将侧栏转为紧凑入口，将辅助信息转为可展开区域，优先保证正文可读。
- 练习期间仍遵守现有离开与保存限制，不通过新侧栏绕过保存流程。
- 第一版不加入自由拖拽面板、多工作区、命令面板或主题自定义快捷键。

### 3. Claude 风格主题

主题显示名称采用 **“Claude 风格”**，说明为非官方视觉预设。

设计方向为暖中性色、克制的陶土强调色、清晰分隔、轻量圆角和舒适阅读宽度。引用对话中的以下色值作为浅色初稿，最终以实际可读性检查调整：

| 用途 | 初稿颜色 |
|---|---|
| 应用背景 | `#F7F6F2` |
| 侧边栏 | `#F0EEE8` |
| 内容表面 | `#FFFFFF` |
| 分隔线 | `#E3DFD7` |
| 主要文字 | `#292724` |
| 次要文字 | `#746E65` |
| 强调色 | `#C66B4E` |

深色模式使用独立配色，不简单反转浅色值。正文、代码、按钮文字、焦点和错误提示分别验证可读性；强调色不能直接假定适合搭配白色小字。

沿用本机可用字体及中文回退字体，不捆绑专有字体或官方品牌素材。主题覆盖板块、题库、练习、学习记录、设置、弹窗、空状态和错误状态。

## 三、技术实现与兼容方案

### 1. 统一主题定义

沿用现有 Electron、React、TypeScript、CSS 变量和共享校验契约，不为主题功能迁移 Tailwind CSS 或整体替换组件库。

建立统一主题定义，内置与外部主题通过同一条渲染路径生效：

- 元信息：格式版本、唯一 ID、名称、主题版本、作者、描述及许可说明。
- 视觉参数：浅色与深色的背景、表面、文字、边框、强调色、状态色、代码高亮和焦点颜色。
- 呈现参数：程序支持的字体预设、圆角档位、间距密度和布局预设。
- 用户字号优先于主题默认值；系统明暗变化只在“跟随系统”模式下生效。

现有四套配色转换为统一主题定义，首批以保持原有呈现为验收目标。主题列表由统一注册来源提供，避免设置页、校验层和样式层各自维护一份主题枚举。

### 2. 本地主题包

第一版主题包采用单个 UTF-8 JSON 文件，扩展名约定为 `.ep-theme.json`，不使用 ZIP。

主题包只包含配置，不接受 JavaScript、HTML、任意 CSS、图片、字体文件、外部资源地址或本地文件路径。颜色和布局参数采用明确的类型与取值范围，拒绝未知字段和不支持的格式版本。

默认限制单包不超过 256 KiB、最多安装 100 个外部主题。缩略预览由程序根据主题配置绘制，不依赖包内截图。

这样，在既定参数范围内增加新主题只需制作主题文件；增加全新的布局能力仍需升级应用。

### 3. 内部接口与数据流

扩展现有共享契约和受限桌面接口：

- 显示设置由固定 `palette` 选择扩展为动态 `themeId`，继续保留明暗模式和字号。
- 新增主题列表读取、选择文件并预检、确认安装或更新、卸载能力。
- 主进程负责文件选择、大小限制、解析校验和持久化；渲染进程只接收已校验的主题数据。
- 安装预检返回已读取内容的预览凭据，确认时使用同一份内容，避免预览后源文件变化。
- 复用现有保存忙碌状态、恢复互斥和正常关闭等待机制；响应丢失时允许安全核对和重试。

主题应用统一生成受控 CSS 变量及布局属性，局部预览与全局显示使用相同的解析结果。

### 4. 存储、迁移与备份

已安装主题的完整配置保存到 SQLite，避免数据库设置与外部主题目录之间产生一致性问题。安装后删除下载文件，不影响已安装主题。

在现有结构 9 基础上增加一次结构迁移：

- 新增外部主题表和当前主题 ID 字段。
- 保留旧 `palette` 字段作为兼容历史数据，迁移时映射到对应内置主题 ID；新代码以主题 ID 为准。
- 保留原明暗模式、字号和全部学习数据。
- 迁移前执行现有一致性保护备份；备份或迁移失败则停止，不重建空库。

同步扩展完整备份校验和恢复摘要，使已安装主题、当前选择及布局偏好随备份恢复。旧备份先在副本中迁移，再进入现有恢复流程。

当前主题缺失或配置损坏时，界面临时使用内置松间绿并明确提示，保留原设置供修复；数据库读取失败仍按错误处理，不能伪装成正常使用默认主题。损坏主题包不能安装，损坏备份不能覆盖当前数据。

## 四、实施顺序与参考来源

按以下批次推进，每批完成对应检查后再进入下一批：

| 批次 | 工作内容 | 完成条件 |
|---|---|---|
| 1. 主题基础 | 统一主题定义、参数解析、内置注册及四套旧主题适配 | 四套主题在明暗、字号和原页面中保持可用 |
| 2. 安装与持久化 | 主题包校验、安装更新卸载、设置迁移、完整备份恢复 | 多个外部主题可并存，关闭重开和恢复后可继续使用 |
| 3. 主题管理界面 | 主题卡片、局部预览、应用反馈及失败重试 | 安装与应用区分清楚，取消和失败不改变当前外观 |
| 4. Claude 风格 | 新增主题预设、学习工作区布局、可折叠导航及辅助面板 | 覆盖全部主要页面，窄窗口可用，原练习流程保持 |
| 5. 回归与交付 | 开发和明确指定的新解包程序验证、文档与使用说明 | 提供完整可运行目录、主题包示例及真实检查结果 |

实施时遵守逐文件开发要求：每完成一个代码文件，分别完成 Bug 检查和可维护性检查，记录后再进入下一个文件；后续实质修改重新检查。

引用对话中的参考项目按以下用途使用：

- [cdesktop](https://github.com/cdesktop-ai/cdesktop)：参考工作区和面板的布局组织。
- [Coide](https://github.com/vicmaster/coide)：参考折叠卡片、上下文面板与复杂内容的呈现。
- [Desktop App Starter](https://github.com/hassancs91/desktop-app-starter)：参考主题参数与组件样式的统一组织。
- [Claude Code Desktop 官方文档](https://code.claude.com/docs/en/desktop)：对照工作区、辅助面板和导航的交互方式。

参考设计方法，按本项目需求实现；需要复用第三方代码时核对对应版本的许可并保留归属。原对话中的搜索、标签和保存常用条件等建议复用当前已有能力，本批不另行扩展搜索或练习功能。

## 五、测试、验收与交付标准

### 必须验证的场景

- **主题管理**：安装至少两个不同的外部主题，依次预览、应用、重开、更新和卸载；删除原主题文件后仍可使用。
- **输入与失败**：损坏文件、超大文件、未知格式、非法参数、重复 ID、版本冲突、数据库写入失败和提交后响应丢失均有明确结果。
- **迁移与恢复**：结构 9 及原有支持的旧结构升级后，旧配色、明暗和字号正确保留；新备份恢复到独立空目录后，主题与学习数据一致。
- **界面覆盖**：五套内置主题及代表性外部主题检查浅色、深色、跟随系统，覆盖最小与最大字号、窄窗口、长代码、长答案、图片、弹窗及错误提示。
- **业务保护**：主题操作不改动题目身份、固定队列、草稿、自评、收藏、历史、分类和方案；新布局不绕过保存，不提前显示答案或答案衍生信息。
- **状态保持**：切换外观及折叠面板不会清空筛选、分页或选中项；字体与布局变化后的阅读位置保持合理可见，键盘焦点不丢失。
- **离线与桌面**：在独立测试目录验证无远程资源依赖；分别记录开发模式、新解包程序和必要的原生窗口人工检查结果。

执行类型与格式检查、单元及数据库测试、相关组件测试、开发和新解包 Electron 回归。保留首轮失败及修正后结果，不通过放宽断言或累加重复次数掩盖失败。

### 最终交付

实施完成后应交付：

1. 支持多主题安装管理的完整 Windows 解包程序。
2. 保留原四套主题，并新增可用的 Claude 风格主题。
3. 两个具有不同视觉风格的可导入示例主题包，用于证明扩展能力。
4. 主题包格式说明、安装更新卸载说明及兼容性说明。
5. 迁移、备份恢复、界面和业务回归的实际结果，以及明确的未验证项。

所有自动化使用独立临时数据库和数据目录。旧程序与历史证据保留；不自动替换个人正在使用的程序或迁移正式学习库。VMware 和此前明确跳过的安装验收继续保持原状态，不因主题功能完成而改记通过。

**完成标准：用户可以在保留学习进度的前提下，安装多个主题、自由选择并持久保存；Claude 风格具有完整的视觉和受控布局表现，后续新增同格式主题无需修改应用代码。**
