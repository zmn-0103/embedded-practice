# 个人嵌入式软件开发刷题程序：V1 产品与 AI 开发计划书

## 一、项目目标与已确定的方向

开发一个供你个人使用的 **Windows 离线刷题程序**。你通过 Markdown 文件建立、维护题目与参考答案知识库，程序负责导入、展示、练习和保存学习记录。

核心使用流程：

**导入题库 → 选择专题或筛选条件 → 阅读题目 → 输入答案或自行思考 → 查看参考答案 → 自评掌握程度 → 下一题。**

本计划基于已经确认的选择：

| 项目 | V1 决定 |
|---|---|
| 使用平台 | Windows 桌面程序 |
| 网络要求 | 安装后，核心功能可以完全离线使用 |
| 题库来源 | 从零建立新题库，不依赖现有题库 |
| 题库维护 | 在程序外编辑 Markdown，再导入或更新 |
| 文件组织 | 每个专题一个 Markdown 文件，文件内包含多道题 |
| 内容类型 | 文字、代码块、表格、本地图片 |
| 作答方式 | 输入答案或只在脑中思考，均可查看参考答案 |
| 学习管理 | 分类筛选、顺序／随机练习、收藏、自评、继续上次练习 |
| 界面方向 | 专注阅读，适合长题目、长答案和代码 |
| AI 的作用 | 协助开发程序、整理题库；程序本身暂不接入大模型 |

**V1 的成功标准：你可以自己维护题库，打开程序就能持续刷题，更新答案不会丢失学习记录，退出重开后能够继续练习。**

本次交付是开发计划。已完成 GitHub 项目与技术文档调研，尚未创建程序、运行参考项目或验证安装包。

## 二、GitHub 参考项目与技术路线

### 2.1 参考项目及借鉴范围

| 项目 | 适合借鉴的部分 | 本项目的处理方式 |
|---|---|---|
| [hashcards](https://github.com/eudoxia0/hashcards) | 纯文本题库；回忆、揭晓、自评的简洁流程 | 借鉴交互流程；采用固定编号保存题目身份 |
| [Essentialist](https://github.com/essentialist-app/essentialist) | Markdown 作为题库来源；按标题组织卡片；离线使用 | 借鉴专题文件组织，增加明确的题目与答案分区 |
| [Anki](https://github.com/ankitects/anki) | 闪卡复习产品形态 | 作为后续复习调度的参考，V1 不引入其完整功能体系 |

hashcards 文档明确说明，它通过内容哈希识别卡片，修改内容会重置该卡片的进度。本项目预计会经常补充、修正参考答案，因此采用固定题目 ID，内容版本与学习记录分别保存。[来源：hashcards README](https://github.com/eudoxia0/hashcards)

Essentialist 使用每个 Markdown 文件作为一组卡片、二级标题作为卡片起点，并将学习进度独立保存。这个组织方式适合你的专题题库，但嵌入式问答通常包含多段题干和代码，所以需要更明确的分区格式。[来源：Essentialist README](https://github.com/essentialist-app/essentialist)

**实现方式：新建独立项目，借鉴上述设计，不直接改造一个完整的开源刷题系统。** 当前调研涉及项目说明、部分入口和依赖配置，不构成对这些项目的完整源码审查或运行验证。

### 2.2 技术选型

| 层次 | 选型 | 用途 |
|---|---|---|
| 桌面外壳 | Electron | 窗口、文件选择、系统集成、打包运行 |
| 界面 | React + TypeScript | 题库、练习、记录与设置页面 |
| 构建 | electron-vite | 构建主进程、预加载脚本和界面 |
| 本地数据库 | SQLite + better-sqlite3 | 保存题库、图片、作答、自评、会话 |
| 题库解析 | unified / remark + YAML 解析器 | 按 Markdown 语法树识别题目结构 |
| 内容展示 | react-markdown + remark-gfm | 展示 Markdown、代码、表格 |
| 代码高亮 | highlight.js | C、C++、汇编等代码的阅读辅助 |
| 输入校验 | Zod | 校验题库元数据及进程间请求 |
| 自动化测试 | Vitest + React Testing Library + Playwright | 纯逻辑、组件和桌面流程验证 |
| Windows 打包 | electron-builder | 生成安装包 |

选择 Electron 的主要考虑是：界面和业务逻辑可以主要使用 TypeScript，适合 AI 分模块开发，也方便实现长答案阅读、代码高亮与导入预览。接受其安装包体积与基础内存占用的代价，V1 不以极小体积为目标。

electron-vite 提供 Electron 主进程、预加载和界面的统一构建配置；electron-builder 负责分发打包。开发时采用经过兼容性验证的稳定版本，并提交依赖锁文件。[electron-vite 文档](https://electron-vite.org/guide/)、[electron-builder 稳定版文档](https://www.electron.build/v26/)

**首先验证“打包后的程序能读写 SQLite”，再开发主要功能。** 这是为了提前发现原生数据库依赖与 Electron 打包之间的兼容问题。

## 三、V1 功能与交互契约

### 3.1 页面结构

程序保留四个主要入口。

| 页面 | 主要内容 |
|---|---|
| 开始练习 | 继续上次练习、专题选择、筛选条件、顺序／随机模式 |
| 题库 | 专题与题目列表、搜索、导入、导入结果、归档管理 |
| 学习记录 | 已练习数量、自评分布、收藏题、单题历史 |
| 设置与数据 | 明暗主题、字号、备份、恢复、数据位置 |

首次启动展示空状态：

- 说明题库尚未导入。
- 提供“导入题库”和“导出题库模板”。
- 不把测试样例自动混入正式题库。
- 允许显式导入单独标识的示例专题。

### 3.2 练习页面

页面从上到下组织为：

1. 专题、题目标题、标签、当前进度。
2. 题目正文。
3. 可收起的“我的答案”输入区。
4. “查看参考答案”按钮。
5. 揭晓后的参考答案区。
6. 自评按钮和上一题、下一题。

具体行为：

- 每道题首次进入时，参考答案默认隐藏。
- 不填写答案，也可以直接揭晓。
- 作答区支持多行纯文本与代码粘贴，V1 不做富文本编辑器。
- 揭晓后保留用户答案，便于对照。
- 已揭晓题目在本轮返回查看时保留揭晓状态；新一轮练习重新隐藏。
- 新一轮不自动展示上次作答；查看历史需主动展开，避免影响回忆。
- 参考答案在揭晓前不挂载到页面正文或无障碍阅读树中。
- 代码块支持复制；图片支持点击放大；表格允许横向滚动。
- 默认跟随系统主题，并允许切换明暗主题。
- 中文正文默认 17px，可调整为 15～22px。
- 常用按钮保持可见，长答案不会把“下一题”挤到难以操作的位置。

### 3.3 自评与完成状态

自评提供三个按钮：

- 不会。
- 不熟。
- 掌握。

另有“暂不评价，下一题”。

规则：

- 自评仅在揭晓答案后可用。
- 点击自评，保存成功后进入下一题。
- 仅查看答案不自动计为“掌握”。
- 跳过或未评价，不自动记为“不会”。
- 自评代表用户主观判断，界面不显示“系统正确率”。
- 同一轮、同一题重复修改自评，更新该条记录，不重复累计练习次数。
- 新一轮练习该题，形成新的历史记录。

学习记录分别显示“已揭晓题数”“已自评题数”和各自评状态数量，避免把不同含义混为一个完成率。

### 3.4 选题、筛选与顺序

支持：

- 按专题。
- 按标签。
- 按难度。
- 按未练习、不会、不熟、掌握。
- 只看收藏。
- 搜索标题、题干、标签。

搜索结果默认不展示参考答案片段。

顺序模式按专题名称、文件内题目顺序排列；随机模式在开始时生成不重复的题目队列，并保存实际顺序。重新打开程序后，恢复原队列，不重新洗牌。

每轮默认 20 题，可选 10、20、50 或全部；不足所选数量时使用全部匹配题目。筛选无结果时显示空状态，不创建空会话。

“收藏”与“掌握程度”彼此独立，掌握的题也可以收藏。

### 3.5 保存与恢复

- 用户输入停止 500ms 后自动保存草稿。
- 切题、揭晓、返回首页和正常退出前，立即提交待保存内容。
- 显示“保存中／已保存／保存失败”。
- 保存失败时保留当前输入，阻止依赖该次保存的切题操作，并提供重试。
- 强制结束进程只能保证恢复已经确认保存的内容，不宣称未提交按键绝不丢失。
- 一次只保留一个可继续的活动会话。
- 已有活动会话时，首页同时提供“继续练习”和“结束本轮并开始新练习”；旧记录保留。
- 运行第二个程序实例时，激活已有窗口，避免两个实例同时操作数据。

V1 不包含自动判分、AI 追问、代码执行、间隔重复、账号、云同步、手机端、在线题库市场和程序内题目编辑。

## 四、新题库的格式与维护规则

### 4.1 文件组织

每个专题一个 `.md` 文件。配图统一放在该文件旁的 `assets` 子目录，例如：

```text
我的嵌入式题库/
  C语言基础.md
  FreeRTOS.md
  STM32外设.md
  assets/
    uart-frame.png
    task-states.png
```

程序支持选择一个或多个 Markdown 文件，批量导入。V1 不做目录监控；修改文件后，用户主动重新导入。

专题名称和标签由题库定义，不在程序中写死。后续增加嵌入式 Linux、驱动或项目题时，无需修改程序代码。

### 4.2 Markdown 格式

使用文件头保存专题信息，二级标题标识一道题，两个固定三级标题分隔题目与参考答案。

以下是格式说明模板；尖括号文字需在正式题库中替换：

```markdown
---
schema_version: 1
topic_id: c-basics
topic_title: C 语言基础
---

## c-001 | <题目标题>

标签：C语言, 指针
难度：基础

### 题目

<完整题目；必要时给出背景、约束、代码和要求。>

### 参考答案

<参考答案正文。>

#### 回答要点

<可以列出需要覆盖的关键点。>

#### 适用条件与来源

<需要时填写平台条件、文档链接或证据边界。>
```

格式契约：

- 文件使用 UTF-8，兼容 BOM、Windows 换行和 Unix 换行。
- `schema_version`、`topic_id`、`topic_title` 必填。
- 题目标题行使用 `## 题目ID | 标题`。
- 题目 ID 在同一专题内唯一。
- 专题与题目 ID 使用小写字母、数字和连字符。
- `标签`可省略，默认为空。
- `难度`可省略，默认为“未分级”；提供时仅允许“基础／进阶／综合”。
- `### 题目`和`### 参考答案`必须各出现一次，且内容非空。
- 题目与答案内部的小节使用四级及更深标题。
- 标签与难度只在题目标题后、题目正文前识别。
- 代码块中的标题或类似标记不参与分题。
- 不支持的格式版本、缺失字段、重复 ID 等必须报告文件名、行号和原因。

**解析器使用 Markdown 语法树确定分区，再保留原始正文文本；不能只用正则表达式按 `##` 切分。**

### 4.3 固定身份与题库更新

题目的稳定身份为：

**`topic_id + question_id`**

文件重命名、标题修改、答案补充、标签调整，不改变这两个 ID，因此不应丢失进度。

导入分为两步：

1. **预览**：展示新增、更新、不变、将归档的题目数量及错误。
2. **确认导入**：全部校验通过后，统一写入。

更新规则：

| 情况 | 行为 |
|---|---|
| 相同 ID、相同内容 | 不重复创建题目 |
| 相同 ID、内容变化 | 更新题目版本，保留收藏和历史记录 |
| 文件中增加题目 | 新增题目，初始为未练习 |
| 同专题新文件缺少已有题目 | 在预览中列为“将归档”，确认后停止参与新练习 |
| 归档题目以相同 ID 再次出现 | 恢复该题并保留历史 |
| 专题标题变化、专题 ID 不变 | 更新名称，保留记录 |
| 修改专题 ID 或题目 ID | 视为新身份；V1 不自动猜测迁移关系 |
| 同批文件含重复专题 ID | 阻止导入，要求先整理文件 |

补充规则：

- 每个专题文件代表该专题的完整快照，不是增量片段。
- 未参与本次导入的其他专题不受影响。
- V1 不永久删除题目与学习记录，使用归档。
- 题干、答案或引用图片变化后，标记“内容更新待复习”，历史自评仍可查看。
- 当前自评只有在其对应内容版本与最新版本一致时，才用于最新掌握状态统计。
- 仅修改标签或显示顺序，不触发“内容更新待复习”。
- 活动会话保留开始时的题目版本，新内容用于下一轮，避免练习中途题目变化。

### 4.4 图片与内容限制

- 图片支持 PNG、JPEG、WebP。
- 引用形式为 `![说明](assets/文件名.png)`。
- 导入时复制图片内容到程序自己的数据库，不长期依赖原文件路径。
- 删除或移动原 Markdown 和配图目录后，已导入内容仍然可用。
- 参考资料中的 HTTP／HTTPS 链接可显示，点击后由系统浏览器打开。
- 远程图片、绝对图片路径、越出 `assets` 的路径、SVG、原始 HTML 和嵌入脚本不进入 V1 支持范围。
- 缺图或不支持的图片引用属于导入错误，避免题目条件悄悄缺失。
- 公式专用排版、Mermaid 渲染后续再加；V1 可用普通文字或图片表达。

默认限制：单个 Markdown 文件 20MiB、单张图片 10MiB、单批导入总大小 200MiB、单批题目 10,000 道。超过限制给出明确提示，不静默截断。

### 4.5 从零建立题库的方法

程序开发与题库内容建设分开推进。

第一批只需要准备 **20～30 道经人工检查的真实题目**，覆盖长答案、代码、表格和图片，用于检验使用体验。大规模扩充在导入和练习流程稳定后进行。

每道正式题目检查：

- 是否有完整问题和必要条件。
- 是否需要指定芯片、操作系统、语言版本或调用场景。
- 参考答案是否直接回答题目。
- 代码、图片和表格是否与答案一致。
- 条件性结论是否写清前提。
- AI 整理的内容是否经过核对。
- 涉及个人项目经历时，是否有事实依据。

程序只能校验格式与关联关系，不能宣称已验证答案的技术正确性。

## 五、架构、数据与内部接口

### 5.1 职责划分

采用以下数据流：

**Markdown 与图片 → 导入校验／预览 → 本地 SQLite → 练习服务 → React 界面**

模块分为：

| 模块 | 职责 |
|---|---|
| 界面 | 展示、输入、阅读布局、反馈保存状态 |
| 预加载桥接 | 暴露明确、有限的桌面能力 |
| 题库服务 | 导入预览、版本更新、查询、归档 |
| 练习服务 | 选题、固定队列、揭晓、自评、会话恢复 |
| 数据访问 | 数据库事务、版本迁移、查询 |
| 资源服务 | 图片校验、保存与受控读取 |
| 备份服务 | 一致性备份、备份验证、恢复 |

主进程负责协调文件和数据操作；界面不能直接访问文件系统或数据库。批量解析与资源处理放入后台工作线程，避免导入大文件时阻塞窗口响应。

### 5.2 数据模型

| 数据实体 | 核心内容 |
|---|---|
| 专题 | 稳定 ID、名称、来源文件信息 |
| 题目 | 稳定身份、当前版本、顺序、标签、难度、归档状态 |
| 题目版本 | 标题、题干 Markdown、答案 Markdown、内容哈希、资源引用 |
| 图片资源 | 内容哈希、类型、尺寸、二进制内容 |
| 练习会话 | 模式、筛选条件、固定题目队列、当前位置、状态 |
| 本轮作答 | 会话、题目版本、草稿、揭晓状态、自评、时间 |
| 用户题目状态 | 收藏、最近自评及其对应版本 |
| 应用设置 | 主题、字号、数据格式版本 |

约束：

- 题目更新与学习记录分开存储。
- 历史作答关联当时的题目版本，能够解释“当时回答的是哪道题”。
- 图片按内容哈希去重，版本引用旧图片时保留旧资源。
- 首次揭晓时间与本轮自评分别记录。
- 草稿保存使用递增修订号，拒绝较旧请求覆盖较新内容。
- 自评与会话位置推进在同一事务中完成。
- 导入题目、版本与图片统一提交；失败则本批次不生效。

### 5.3 内部接口

V1 没有公网 API，通过受限的桌面桥接接口访问服务：

| 接口 | 输入与行为 |
|---|---|
| `library.previewImport` | 打开文件选择，返回预览令牌、变更摘要和错误 |
| `library.commitImport` | 根据预览令牌提交已校验快照 |
| `library.listQuestions` | 根据专题、标签、状态等分页查询 |
| `practice.start` | 根据模式、筛选条件和数量创建固定队列 |
| `practice.resume` | 恢复活动会话 |
| `practice.saveDraft` | 保存本轮输入及修订号 |
| `practice.reveal` | 保存揭晓状态并返回对应版本参考答案 |
| `practice.rateAndAdvance` | 保存自评并推进位置 |
| `practice.navigate` | 保存当前状态后切换上一题／下一题 |
| `question.setFavorite` | 设置收藏状态 |
| `history.list` | 返回单题历史作答及内容版本 |
| `backup.export` | 创建一致性备份 |
| `backup.restore` | 校验备份并执行恢复 |

预览成功后使用已暂存、校验的内容提交；不能在用户确认时重新读取可能已变化的源文件而不告知。

接口使用共享 TypeScript 类型，并在主进程重新校验输入。错误统一包含错误码、中文说明和必要定位信息；堆栈仅写入本地诊断日志。

### 5.4 本地保存与备份

- 数据放在 Electron 的用户数据目录，与安装目录分离。
- 数据库内保存题目、图片、学习记录和设置，使备份能够覆盖完整状态。
- 导出备份使用 SQLite 一致性备份能力，不能直接复制正在写入的数据库文件来冒充完整备份。[better-sqlite3 事务与备份文档](https://github.com/WiseLibs/better-sqlite3/blob/master/docs/api.md)
- 备份包含应用标识和数据库结构版本。
- 恢复前检查文件完整性、应用标识和版本兼容性，显示题目数量及备份时间。
- 恢复前自动备份当前数据；无法完成保护性备份时不继续恢复。
- 恢复采用暂存、校验、关闭连接、替换与失败回退流程，处理数据库伴随文件。
- 恢复成功后重新启动程序；损坏或更新版本的备份不得覆盖当前数据。
- 升级时在迁移数据库前备份；迁移失败保留原数据并提示，不自动重建空数据库。

### 5.5 桌面与内容边界

启用上下文隔离、渲染进程沙箱，关闭界面的 Node.js 集成；预加载层只暴露白名单接口，并校验调用来源。这与 Electron 官方建议一致。[Electron 安全文档](https://www.electronjs.org/docs/latest/tutorial/security)

Markdown 通过受控组件展示，图片只能访问已导入的资源 ID；不把题库内容当作可执行页面。程序默认不包含遥测、云请求或自动更新服务。

## 六、适合 AI 执行的分阶段开发任务

各阶段必须有可观察的结果与验收证据。前一阶段关键验收未通过时，先修复，再继续后续功能。

### M0：建立工程并验证打包链路

**任务**

- 创建独立项目，暂定名“嵌入式刷题本”。
- 建立 Electron、React、TypeScript、electron-vite 工程。
- 接入 SQLite，验证创建、写入、关闭和重开读取。
- 建立受限预加载接口。
- 建立开发、检查、测试、构建和 Windows 打包命令。
- 记录选定版本，提交依赖锁文件。
- 建立产品说明、题库格式说明和验收记录。

**验收**

- 开发模式能启动。
- Windows 打包产物能启动。
- 打包产物能保存测试数据并在重启后读回。
- 安装后的使用不依赖用户另行安装 Node.js。

### M1：实现题库格式与导入

**任务**

- 固定 Markdown V1 格式和校验规则。
- 实现语法树解析、错误定位、图片读取与限制校验。
- 实现导入预览、确认提交和事务。
- 实现相同内容重复导入、内容更新、缺题归档。
- 提供空模板、格式示例和解析测试夹具。

**验收**

- 文字、代码、表格、图片完整导入。
- 代码块中的伪标题不被识别为新题目。
- 无效文件不会产生半批数据。
- 相同题库重复导入不增加题目数量。
- 答案更新不丢失收藏和历史。
- 原文件移动后，已导入图片仍然可用。

### M2：完成核心刷题闭环

**任务**

- 实现选题、阅读、输入、揭晓、自评和切题。
- 实现长文本排版、代码高亮、图片放大。
- 实现草稿自动保存与保存状态提示。
- 完成顺序模式。

**验收**

- 输入和纯思考两种方式均可完成练习。
- 未揭晓前页面不包含参考答案正文。
- 自评、暂不评价和跳过行为符合约定。
- 连续点击不产生重复记录或跳过多题。
- 保存失败时不丢弃当前输入。

### M3：加入轻量学习管理

**任务**

- 实现筛选、搜索、收藏和自评状态筛选。
- 实现不重复随机队列。
- 实现活动会话恢复。
- 实现单题历史、内容更新待复习标记。
- 实现明暗主题、字号设置和输入区折叠。

**验收**

- 随机队列本轮不重复，重启后顺序不变。
- 保存后的草稿、位置、自评和收藏可以恢复。
- 新一轮默认隐藏参考答案及历史作答。
- 当前会话内容不被题库更新中途替换。
- 搜索与筛选不泄露答案摘要。

### M4：备份、恢复与异常处理

**任务**

- 实现完整备份及恢复预览。
- 实现恢复前保护性备份和失败回退。
- 加入数据库迁移框架。
- 处理损坏备份、写入失败、缺图、路径越界等异常。
- 完成单实例限制与本地诊断日志。

**验收**

- 在全新数据目录恢复后，题目、图片、作答和收藏一致。
- 无效备份不会破坏现有数据。
- 导入失败与保存失败的提示能够指导用户处理。
- 日志默认不记录完整题目与用户答案。

### M5：真实题库试用与发布交付

**任务**

- 使用你重新建立的 20～30 道真实题目试用。
- 修正阅读体验和操作问题。
- 使用生成数据检查较大题库性能。
- 生成 Windows x64 安装包。
- 完成安装、重启、离线、升级保留数据的验证。
- 整理使用说明、开发说明、已知限制和验证记录。

**验收**

- 安装包能够在约定的 Windows 环境运行。
- 断网完成导入、练习、退出重开及备份恢复。
- 中文路径、含空格路径可用。
- 卸载默认保留用户数据；重新安装后仍可读取。
- 交付包明确标注是否签名，不把“已打包”描述成“已完成签名或发布”。

## 七、测试与最终验收清单

### 7.1 必须覆盖的测试场景

| 类别 | 重点场景 |
|---|---|
| 解析 | 中文、BOM、不同换行、多行代码、表格、嵌套列表、代码内伪标题 |
| 格式错误 | 缺题干、缺答案、重复 ID、未知版本、不合法难度、无效 YAML |
| 资源 | 中文图片名、缺图、超大图片、越界路径、远程引用、不支持类型 |
| 更新 | 重复导入、只改答案、只改标签、删除题目、恢复归档题、文件重命名 |
| 练习 | 纯思考、输入后揭晓、跳过、返回上一题、修改自评、最后一题结束 |
| 状态保存 | 连续输入、快速切题、正常退出、强制结束后恢复已保存状态 |
| 并发交互 | 重复点击、旧草稿请求晚到、自评提交重试 |
| 备份恢复 | 完整恢复、损坏文件、版本不兼容、恢复失败回退 |
| 桌面运行 | 安装包启动、数据库依赖加载、离线、中文路径、显示缩放 |

### 7.2 验证层次

- **单元测试**：解析、身份匹配、变更比较、队列生成、统计口径。
- **数据库集成测试**：事务、版本保留、幂等、自评与推进一致性。
- **组件测试**：答案隐藏、空输入允许揭晓、错误提示与按钮状态。
- **桌面流程测试**：从导入到重启恢复的完整路径。
- **人工检查**：真实安装包、长答案阅读、图片缩放、中文输入法和 Windows 显示缩放。

Playwright 提供 Electron 自动化接口，但其 Electron 支持标为实验性；自动化通过后仍需真实安装包人工检查。[Playwright Electron 文档](https://playwright.dev/docs/api/class-electron)

### 7.3 性能验收目标

使用 5,000 道生成题目、500 张小图片作为压力样本，记录测试电脑配置与数据大小。

- 本地常规题目切换目标小于 200ms。
- 普通搜索目标小于 500ms。
- 正常启动至可操作目标小于 3 秒。
- 导入显示进度，窗口能够响应。
- 列表分页，图片按需读取，避免一次加载全部答案和图片。

以上是开发目标，验收时报告实测结果。未达到时定位原因，不用目标数值冒充已经测得的性能。

## 八、AI 开发协作方式与交付物

### 8.1 每次开发任务的固定内容

交给 AI 的每个任务应包含：

| 内容 | 要求 |
|---|---|
| 当前阶段 | 明确 M0～M5 中的哪一阶段 |
| 本次目标 | 一到两个可观察的结果 |
| 前置事实 | 当前代码、已通过检查、已知限制 |
| 修改范围 | 允许修改的模块及不可改变的接口 |
| 行为约定 | 输入、输出、保存时机和失败表现 |
| 验收条件 | 能重复执行的场景与预期结果 |
| 完成报告 | 实际改动、实际检查、失败、未验证项 |

执行节奏：

1. 先阅读项目规则和相关模块。
2. 将本阶段行为与测试场景写清楚。
3. 实现最小完整功能。
4. 执行对应检查。
5. 修复失败后提供可运行结果。
6. 记录状态，再进入下一阶段。

用户负责确定学习体验、审阅正式题库和验收真实使用流程；AI 负责按契约实现、补充测试和整理证据。涉及嵌入式知识内容时，需单独核对技术依据。

### 8.2 开发过程中必须保持的约束

- 未经需求变更，不增加 AI 判分、云服务、账号或复习算法。
- 不通过简化题库格式来规避代码块、图片和长答案问题。
- 不用占位数据替代实际数据库闭环。
- 不用浏览器截图替代桌面安装包验证。
- 不把“构建通过”写成“所有功能通过”。
- 测试不得连接或覆盖正式用户数据库。
- 样例、压力测试数据与真实题库明确区分。
- 开发文档与实现同步更新，避免 AI 后续依赖过期约定。
- 如复用第三方代码，保留所需许可与来源信息。

### 8.3 最终交付清单

1. 完整源代码及依赖锁文件。
2. Windows x64 安装包。
3. Markdown V1 题库格式说明。
4. 可直接填写的专题模板及格式示例。
5. 使用说明：建立题库、导入、更新、练习、备份恢复。
6. 开发说明：环境、运行、测试、构建与打包。
7. 数据模型及内部接口说明。
8. 自动化测试与实际运行记录。
9. 已知限制和未验证项。
10. 后续版本候选清单。

### 8.4 默认假设与后续边界

- V1 面向个人、单机、单用户，发布验证以 Windows 11 x64 为默认环境。
- 项目暂定名称为“嵌入式刷题本”，内部标识为 `embedded-practice`。
- 正式题库重新建立，本计划不承诺生成完整嵌入式题库。
- 程序不修改导入来源文件。
- Markdown 是题目内容的维护来源，应用数据库是导入副本和学习记录的保存位置。
- 数据库历史版本暂不自动清理，优先保证可追溯和可恢复。
- 初版交付本地安装包，不自动上传 GitHub、发布商店或配置云服务。
- 后续优先考虑间隔复习、程序内题目编辑、题库质量检查；跨设备同步和 AI 评阅另行设计。

**V1 的完成门槛是：你能用自己新建的题库连续完成练习，并经过一次题库更新、一次程序重启和一次备份恢复，题目内容与学习记录都符合上述约定。**
