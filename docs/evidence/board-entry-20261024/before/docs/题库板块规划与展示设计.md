# 题库板块规划与展示设计

日期：2026-10-24。按用户提供的两套软件截图设计：前2张属于第一套，后3张属于第二套。采用15个基础板块、7个拓展方向，允许先有空板块，后续逐专题补题。本轮交付规划清单与独立预览，正式EXE及个人库未修改。

## 一级板块与专题范围

基础与拓展只是首页展示分组，不是新的树层级。程序内仍采用“板块 → 专题”，标签表达跨专题考点。每个专题只归一个板块；同一题不为了多个入口复制成多份。下面的专题名是建设目录，不代表已经创建题库。

## 对参考软件分类的取舍

| 参考分类 | 本项目安排 |
| --- | --- |
| 嵌入式基础面试题、热门必刷题 | 按主要知识归入语言、外设、架构等板块；入门/高频作为标签或练习方案，不再复制一套题。 |
| 单片机、STM32、ARM架构 | 分为MCU通用外设、具体平台与SDK、处理器架构三种回答能力。STM32成为平台专题族。 |
| RTOS、操作系统、内存管理、多线程与并发、进程与线程 | 通用调度/并发和RTOS放“RTOS与并发”；Linux API和内核实现各归其板块；内存问题按语言、架构或系统上下文分专题。 |
| Linux、Linux系统编程、Linux内核、Linux驱动 | 合为用户态“Linux系统与应用”和内核态“Linux内核与驱动”两块，避免首页同时出现多张范围接近的卡片。 |
| 通信协议、通信与网络、计算机网络 | 分开设备总线/串行协议与TCP/IP网络。RS-485等物理接口要与上层帧协议分别说明。 |
| 嵌入式硬件、硬件基础、硬件接口、PCB/硬件设计基础 | 共性电路、原理图、PCB和电气约束归“硬件与电路基础”；外设工作原理、通信帧规则仍归对应软件板块。 |
| Shell/脚本、Python、编译与调试、工程实践 | 第一版作为“编译调试与工程实践”的专题；后续确有独立语言学习规模时再评估拆板块。 |
| 存储技术、安全与加密 | 存储为基础板块；安全和可靠性为拓展方向。 |
| 信号处理、DSP、图像处理/多媒体 | 合为“信号处理与多媒体”，用专题区分。 |
| 蓝牙、WiFi | 合为“无线与物联网”，保留各自专题。 |
| 电机控制、电力电子 | 合为“控制与电力电子”；机器人、无人机另设系统应用方向。 |
| 汽车电子/AUTOSAR、机器人、无人机、FPGA | 保留为相应拓展方向，不以当前没有题库为由删除规划。 |
| 项目经验 | 使用“项目与面试表达”，只记录真实经历或明确标注的假设案例。 |

## 卡片和空板块的表现

- 首页先显示15个基础板块，拓展方向通过“显示拓展方向”展开；搜索覆盖板块名与规划专题名。拓展关闭时的无结果提示会提醒显示拓展。
- 卡片显示名称、范围短句、内容状态和查看专题入口。空板块保持可查看，展开后列出待建设专题及收题边界。
- 接入真实程序后，题数应来自本机实际导入的活动题目；0题显示“待补题”，不进入空练习。规划清单和其他软件截图中的题数不得当成本机题数。
- 本次独立预览显示的是仓库候选题数量，并已在顶部说明。118题都不因此取得用户技术审阅或学习完成状态。
- 规划的专题没有题目时只保存名称，不生成占位题或无法导入的空Markdown。实际建库仍遵守完整专题快照和格式校验。

## 维护与后续

规划单一维护源为 `question-banks/catalog/板块规划.json`。其中key是规划键，不是数据库category_id；plannedTopics只是待建名称。预览通过现有清单生成，使用新文件名避免覆盖已有设计快照：

```powershell
node scripts/render-board-design.mjs docs/design/board-catalog-next.html
```

本轮先完成分类设计；后续接入程序默认入口和按清单建立本机分类属于单独实现批次。当前分类树已能手动建立0题板块，但本轮没有自动向个人库写入22个分类，也没有修改当前程序首页。补题时优先扩充语言、通用外设和通信基础，拓展方向按实际学习需求逐步建设。

静态范围检查与浏览器预览检查见[本批证据](evidence/board-design-20261024/README.md)。这不是Electron程序回归、安装、硬件或用户体验验收。
