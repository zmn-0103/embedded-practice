**剩余问题及可直接交给开发的优化指令如下。尺寸是下一轮建议目标，不代表已经实现。**

**1．题库分类栏还有两层嵌套滚动，建议优先处理。**

当前分类栏外层能滚动，里面的分类树又能单独滚动。实测外层可视高度约 473 像素、内容高度 651 像素；内层分类树可视高度约 374 像素、内容高度 579 像素。

这会让鼠标停在不同位置时，滚动对象发生变化。题库本身已有题目列表和详情的独立滚动，再叠加分类栏内部的两层滚动，操作显得复杂。

优化指令：

- 分类列只保留一个主要纵向滚动区域。
- 将“分类与专题”、分类搜索框放在列顶部；分类树占据剩余空间并滚动。
- 移除分类树与父容器同时设置的滚动高度限制，避免同一列出现两根纵向滚动条。
- 压缩分类说明文字的常驻占用，可改成简短提示或帮助说明。
- 题目列表和详情继续独立滚动，保留本轮已经修好的选中题目定位、列表位置保持行为。

验收要求：分类很多、树节点展开、搜索过滤后，同一分类列始终只有一处主要滚动区域；点击第 20 题后的详情定位不能回退。

当前实际画面：[题库分类栏与三栏布局](</E:/My_Projects/embedded-practice/output/playwright/ui-reference-recheck-20261026/followup/22-library-first-row-1440-17.png>)。

**2．知识板块在“有未完成练习”时，首屏仍被顶部内容占用过多。**

这是补查时发现的明显差异：

- 没有活动练习时，第一排板块卡片从约 **459 像素**处开始。
- 有活动练习时，新增“继续练习”大卡，第一排被推到约 **699 像素**处。
- 第二排从约 **904 像素**处开始，在 900 像素高的窗口中已经完全落到首屏之外。

下面是本轮实际截图。可以看到，进入“知识板块”后，主要空间仍被继续练习、标题、说明、搜索和计数占据：

![知识板块有未完成练习时的实际首屏](</E:/My_Projects/embedded-practice/output/playwright/ui-reference-recheck-20261026/followup/23-boards-1440-17.png>)

优化指令：

- 在“知识板块”页，把继续练习卡压缩成紧凑横条：左侧显示专题、当前进度，右侧保留“继续练习”。
- “本轮创建条件”继续支持展开，但默认收起时不要为它预留大片空白。
- 页面标题、题库总数、导入入口合并为紧凑的标题工具区。
- 搜索与“显示拓展方向”放在同一工具行；题数来源、分类规则等长说明收进帮助提示。
- 增加“仅显示有题板块”的筛选，或将已有题目的板块优先展示；**只调整展示，不自动改动分类归属**。
- 卡片描述限制为适合浏览的短摘要，卡片底部操作对齐，减少当前不同卡片高度不一致的现象。

建议验收目标：1440×900、17 字号、有活动练习时，第一排卡片尽量在 **400～450 像素以内**开始，并能看到两排主要板块；22 字号下允许自然增高，不能截断文字。

**3．“保存并返回”解决了进入页面时的可见性，但长答案读到底后仍不方便返回。**

在 900×900、22 字号下滚到答案末尾：

- 底部自评操作栏仍可见；
- 答案末尾没有被操作栏遮住；
- 顶部“保存并返回”已滚到视口上方，需要向上滚动才能点击。

因此，这不是保存失效，而是操作路径还可以缩短。

优化指令：

- 将练习顶部的紧凑操作行设为滚动时保持可见；或者在底部操作栏增加一个次级“保存并返回”入口，二选一即可。
- 返回入口不要比“揭晓答案”“自评并继续”等主要操作更突出。
- 新入口复用现有保存与返回逻辑，保留保存失败、处理中和草稿保护行为。
- 窄窗按钮换行后继续计算底部占位，避免新增按钮遮挡答案。

验收要求：在题目顶部、答案中部和答案末尾，都能直接找到返回入口；无需先滚回页面顶部；失败时仍保留当前输入与题目状态。

证据：[窄窗答案末尾实际画面](</E:/My_Projects/embedded-practice/output/playwright/ui-reference-recheck-20261026/followup/21-reading-answer-bottom-900-22.png>)。

**4．窄窗未揭晓页面和题库列表，信息密度仍有优化空间。**

窄窗短题的“揭晓答案”位置比上轮有所改善，但仍需要向下滚动：

| 窗口与字号 | 本轮揭晓按钮顶部位置 |
|---|---:|
| 900×900，17 字号 | 约 942 像素 |
| 900×900，22 字号 | 约 1001 像素 |

真实题目的列表项也仍有较多重复元信息，单条经常占用约 100～130 像素，首屏只能浏览少量题目。当前功能可用，但与参考图中紧凑、便于扫描的题库列表还有差距。

优化指令：

- 窄窗练习页压缩标题区、题目属性、辅助说明之间的垂直间距。
- 草稿状态、题号进度、收藏等辅助信息优先合并成紧凑工具行。
- 保留正常字号和足够的输入区域，不通过缩小正文来换取首屏空间。
- 短题可考虑让“揭晓答案”进入稳定可见的操作区；长题允许自然滚动，不强求所有内容挤进一屏。
- 题库列表按“题名为主、元信息为辅”整理：第一行题名，下一行组合题号、难度、自评、收藏状态。
- 当当前专题已明确时，列表中完整专题名称可弱化或简写，完整信息保留在详情中。
- 普通短标题条目可争取控制在 **72～88 像素**，长标题自然增高，不能强行裁掉关键内容。

验收要求：短题的主要操作更容易找到；列表能显示更多题目；22 字号和长中文标题下不重叠、不截断，不损失可访问的完整信息。

**下一轮建议按这个顺序处理：分类栏单层滚动 → 长答案返回入口 → 知识板块顶部压缩 → 窄窗与列表密度。** 已修好的题目定位、自评栏留白、设置页签和窄窗导航行为应作为回归保护项保留。
