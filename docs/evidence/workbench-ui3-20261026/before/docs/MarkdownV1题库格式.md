# Markdown V1 题库格式说明

当前状态（2026-10-20）：已实现 AST 解析、文件/图片验证、后台快照、预览令牌与摘要、事务提交、幂等、版本/归档及图片入库，并已接通受限 IPC、窗口、模板导出与受控展示。开发构建与 Windows 解包程序各 19 项真实场景通过；人工正式题库审阅与体验待完成，使用方法见[导入与更新](使用说明.md)。

本说明保留用户[计划书第四章](../计划书.md)的 4.1～4.4 格式与更新契约，实际实现后同步补充错误示例与验证结果。

### 4.1 文件组织

每个专题一个 `.md` 文件。配图统一放在该文件旁的 `assets` 子目录，例如：

```text
我的嵌入式题库/
  C语言基础.md
  FreeRTOS.md
  STM32外设.md
  assets/
    uart-frame.png
    task-states.png
```

程序支持选择一个或多个 Markdown 文件，批量导入。V1 不做目录监控；修改文件后，用户主动重新导入。

专题名称和标签由题库定义，不在程序中写死。后续增加嵌入式 Linux、驱动或项目题时，无需修改程序代码。

### 4.2 Markdown 格式

使用文件头保存专题信息，二级标题标识一道题，两个固定三级标题分隔题目与参考答案。

以下是格式说明模板；尖括号文字需在正式题库中替换：

```markdown
---
schema_version: 1
topic_id: c-basics
topic_title: C 语言基础
---

## c-001 | <题目标题>

标签：C语言, 指针
难度：基础

### 题目

<完整题目；必要时给出背景、约束、代码和要求。>

### 参考答案

<参考答案正文。>

#### 回答要点

<可以列出需要覆盖的关键点。>

#### 适用条件与来源

<需要时填写平台条件、文档链接或证据边界。>
```

格式契约：

- 文件使用 UTF-8，兼容 BOM、Windows 换行和 Unix 换行。
- `schema_version`、`topic_id`、`topic_title` 必填。
- 题目标题行使用 `## 题目ID | 标题`。
- 题目 ID 在同一专题内唯一。
- 专题与题目 ID 使用小写字母、数字和连字符。
- `标签`可省略，默认为空。
- `难度`可省略，默认为“未分级”；提供时仅允许“基础／进阶／综合”。
- `### 题目`和`### 参考答案`必须各出现一次，且内容非空。
- 题目与答案内部的小节使用四级及更深标题。
- 标签与难度只在题目标题后、题目正文前识别。
- 代码块中的标题或类似标记不参与分题。
- 不支持的格式版本、缺失字段、重复 ID 等必须报告文件名、行号和原因。

**解析器使用 Markdown 语法树确定分区，再保留原始正文文本；不能只用正则表达式按 `##` 切分。**

当前实现还明确检查：文件头之后直接开始题目（允许 Markdown 引用定义），不接受独立前言；标签和难度不能重复；只含标题、分隔线或引用定义的正文不算非空。分区边界空行会移除，代码缩进、CRLF/LF、正文换行和行尾双空格保留。原始 HTML 在文件内均拒绝，代码块/行内代码中的 HTML 字符串只是文本。

引用式图片如 `![说明][board]` 也可静态解析；采用 Markdown 标识规范与首个定义，专题解析结果保留引用定义供后续受控渲染。真实文件读取仍需资源服务验证，静态解析成功不能替代缺图、类型、大小或实际路径检查。

第二批准备入口已经执行资源验证：拒绝缺图、非普通文件、Windows 设备名/非法文件名、越界真实路径及 `assets` 根目录指向别处的 junction；允许实际目标仍在 `assets` 内的子目录链接。按文件签名与头部读取三种图片的类型/尺寸，要求与引用后缀一致，并验证 WebP 的 RIFF 长度。该检查不是完整像素解码或所有损坏检测。实际校验字节纳入返回快照，并按 SHA-256 去重，来源改动不替换已返回的内容。

错误示例：`schema_version: 2` 返回 `INVALID_METADATA`；重复 `## gpio-001 | ...` 返回 `DUPLICATE_ID`；缺 `### 参考答案` 返回 `INVALID_QUESTION`；远程图片返回 `UNSUPPORTED_CONTENT`。每个错误包含文件名、行、列和原因；有任一错误时不返回部分专题。

### 4.3 固定身份与题库更新

题目的稳定身份为：

**`topic_id + question_id`**

文件重命名、标题修改、答案补充、标签调整，不改变这两个 ID，因此不应丢失进度。

导入分为两步：

1. **预览**：展示新增、更新、不变、将归档的题目数量及错误。
2. **确认导入**：全部校验通过后，统一写入。

更新规则：

| 情况 | 行为 |
|---|---|
| 相同 ID、相同内容 | 不重复创建题目 |
| 相同 ID、内容变化 | 更新题目版本，保留收藏和历史记录 |
| 文件中增加题目 | 新增题目，初始为未练习 |
| 同专题新文件缺少已有题目 | 在预览中列为“将归档”，确认后停止参与新练习 |
| 归档题目以相同 ID 再次出现 | 恢复该题并保留历史 |
| 专题标题变化、专题 ID 不变 | 更新名称，保留记录 |
| 修改专题 ID 或题目 ID | 视为新身份；V1 不自动猜测迁移关系 |
| 同批文件含重复专题 ID | 阻止导入，要求先整理文件 |

补充规则：

- 每个专题文件代表该专题的完整快照，不是增量片段。
- 未参与本次导入的其他专题不受影响。
- V1 不永久删除题目与学习记录，使用归档。
- 题干、答案或引用图片变化后，标记“内容更新待复习”，历史自评仍可查看。
- 当前自评只有在其对应内容版本与最新版本一致时，才用于最新掌握状态统计。
- 仅修改标签或显示顺序，不触发“内容更新待复习”。
- 活动会话保留开始时的题目版本，新内容用于下一轮，避免练习中途题目变化。

第四批已实现上述导入和数据库版本边界，详见[预览与提交](architecture/M1预览与提交.md)。标题、难度、标签、顺序按元数据更新，不生成内容版本；题干、答案、实际所用引用定义与图片内容哈希参与版本比较，仅统一 CRLF/LF。预览默认 15 分钟，确认使用私有快照，旧数据库基线必须重新预览。第五批已展示摘要与活动/归档题库；M2 第一批已用真实会话/作答行验证固定旧版本与状态保留，但练习窗口和历史查询仍待后续批次。

### 4.4 图片与内容限制

- 图片支持 PNG、JPEG、WebP。
- 引用形式为 `![说明](assets/文件名.png)`。
- 导入时复制图片内容到程序自己的数据库，不长期依赖原文件路径。
- 删除或移动原 Markdown 和配图目录后，已导入内容仍然可用。
- 参考资料中的 HTTP／HTTPS 链接可显示，点击后由系统浏览器打开。
- 远程图片、绝对图片路径、越出 `assets` 的路径、SVG、原始 HTML 和嵌入脚本不进入 V1 支持范围。
- 缺图或不支持的图片引用属于导入错误，避免题目条件悄悄缺失。
- 公式专用排版、Mermaid 渲染后续再加；V1 可用普通文字或图片表达。

默认限制：单个 Markdown 文件 20MiB、单张图片 10MiB、单批导入总大小 200MiB、单批题目 10,000 道。超过限制给出明确提示，不静默截断。

第二批批次准备按 Markdown 与不同规范化图片源路径计算来源大小；同图重复引用计一次，同内容不同路径仍分别计大小，但结果资源按内容去重。同批重复专题拒绝；处理遇到首个失败文件即停止，不返回部分成功快照。已经提供[可填写模板](../question-banks/templates/README.md)与[真实配图示例](../question-banks/examples/README.md)，窗口可导出同一模板。模板含占位正文，填写并人工核对后再作正式题库。

第五批窗口通过版本 ID/资源哈希读取数据库图片，不使用来源路径。中文与编码空格引用通过同一单次解码规则匹配；真实 PNG/JPEG/WebP 小图均已在 Electron 解码。仅有合法头部但像素损坏的图片可能通过导入校验，展示时明确提示“图片无法解码或读取”，不能把导入成功理解成全部图片完成像素验证。参考链接仅显式点击已验证 HTTP/HTTPS 时交给系统浏览器。
