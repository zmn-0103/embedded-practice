# M4 恢复执行与回退

日期：2026-10-22。正式结构 6、依赖/锁文件和原练习草稿控制器保持；本次扩展备份链路，复用现有保存握手、迁移与一致性备份。实际结果与边界分别见[行为与验收](../M4第二批行为与验收.md)和[原始证据](../evidence/m4b/README.md)。

## 窗口与预览凭据

`BackupPanel → preload → registerBackupIpc → restoreBackup`。导出仍为零参数；预览返回路径、摘要和 UUID，恢复只接受严格 `{ token }`，不能提交路径或 SQL。原生确认展示所见备份、题数、图片数、时间及覆盖/重启说明，默认取消。来源须为可信主页面；确认期间关闭、导航或渲染销毁使凭据失效，重复操作返回忙碌。

预览在自有目录保留一份已迁移、完整校验的副本及 SHA-256，转为 DELETE 日志后关闭连接。摘要继续显示源结构和原备份时间；副本的 manifest 结构字段同步为迁移后的版本。确认后不重新读取外部文件。新选择、导出或导航丢弃旧预览；恢复接管副本时消费凭据，接管后的清理责任转给恢复流程。副本被改动时拒绝并要求重新预览。

允许直接选择当前数据目录 `backups/` 下的独立保护备份进行预览与恢复；导出仍不能写入运行目录。当前库及其硬链接别名、带伴随文件的来源、其他运行内部文件继续拒绝，不能借这项只读例外把运行数据库当备份。

## 保存、保护与连接关闭

主进程拒绝与正常退出并发的恢复。先调用练习关闭握手：沿用控制器刷新最新草稿，等待已经发起的显示保存；失败时取消恢复并通知窗口复位关闭状态。随后暂停练习和题库/设置请求、取消文件准备并排空已有异步任务，防止保护快照之后仍有业务写入。

`prepareRestore` 再核对副本哈希及全部现有备份校验项，调用同一 SQLite backup 流程在当前数据目录 `backups/` 生成唯一 `before-restore-*.sqlite3` 并完整验证。该文件独立保留，不随恢复暂存清理。保护失败时不关闭业务连接、不移动当前数据，恢复请求通道可返回错误，业务请求和窗口操作恢复。

保护完成后依次关闭备份只读连接、练习 IPC/连接、题库 IPC/工作线程/连接、图片入口和启动连接。尝试释放全部连接并汇总失败；任何连接未确认关闭都禁止替换并重启原数据。恢复处理器不调用等待自身完成的备份 IPC 关闭过程，避免死锁。

## 文件事务和启动恢复

`restore-files.ts` 仅处理应用自己的固定 `practice.sqlite3`、三个伴随后缀及同卷 `restore-transaction/`。拒绝目录链接、非普通文件、未知目录内容和已有未完成事务，所有记录只含固定后缀与哈希。

1. 将已校验副本复制进事务目录，刷写并核对哈希。对关闭后的原主文件及实际存在的 WAL/SHM/journal 逐个记录哈希。
2. 将 `prepared` 记录写入、刷写并通过 rename 发布之后，才逐个移动原文件到事务目录。
3. 安装副本，以只读连接重新检查完整性/应用标识/版本/业务内容，关闭后复核文件哈希。没有写入中的连接参与替换。
4. 刷写并发布 `committed` 记录，再清理已核对的原文件和事务目录。保护性备份始终保留。提交后的清理失败留给启动重查，不把已提交恢复改写为失败。

提交前失败或中断时，启动在打开任何会自动建库的服务之前核对全部回退来源及目标。原件已移动则移回；尚未移动或已完成回退的文件必须与记录哈希一致。新安装副本移入事务目录，原主文件与伴随文件按原名恢复。部分移动及部分回退可重入；原件缺失/变化、未知伴随文件或坏记录时停止启动，保留现场，不能创建空库掩盖问题。

已提交事务的启动收尾要求目标哈希一致且没有未知伴随文件；仍在的原件也须核对才可删除。发生自动回退失败时保留现场并退出，下次进程先重新检查，不能在当前窗口继续使用部分关闭的服务。

## 重启与验证边界

成功恢复或确认回退后使用官方 `app.relaunch({ args })`，待当前进程退出后启动新进程；不沿用原开发调试端口。重启安排在接口响应之后，避免主进程关闭接口时自等待。官方行为见[Electron app 文档](https://www.electronjs.org/docs/latest/api/app/#apprelaunchoptions)。

测试区分真实自动 relaunch 后连接新进程与“阻止自动 relaunch 后由测试独立启动”的故障检查。业务比较包含 12 个业务表、资源字节；`app_startup` 按正常启动增加，不要求启动计数回到原值。伴随文件另有合成字节回退检查，不能据此声称覆盖所有真实 WAL/文件系统/杀毒软件锁定情形。已测试进程中断，不把文件刷写或进程退出视为实际断电试验。原生确认与选择框的自动化替身也不代签完整人工体验。
