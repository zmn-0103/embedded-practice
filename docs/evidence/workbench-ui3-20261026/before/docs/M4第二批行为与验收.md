# M4 第二批：恢复执行、保护性备份与失败回退

日期：2026-10-22。用户授权继续开发，承接 M4 第一批。

## 范围与验收目标

- 保留预览时已校验并升级的独立副本，以一次性凭据确认；恢复不重新读取外部源文件。
- 确认前展示摘要与覆盖/重启说明，原生确认默认取消。恢复前完成草稿/设置保存并暂停业务请求；保存或保护性一致性备份失败时停止替换，返回可操作窗口。
- 严格关闭全部数据库连接后，按暂存、持久事务记录、原文件及伴随文件保留、替换、校验、提交执行。失败恢复原文件；启动时先处理未完成替换，不能因主文件暂缺而初始化空库。
- 成功后自动重启；保护性备份独立保留。仅使用隔离临时数据测试成功、取消、源变化、保护失败、替换失败、回退、中断和全新目录恢复。
- 保留原 526 单元和开发/解包各 123 项场景。结构仍为 6，依赖、锁文件、正式需求原文保持。不执行正式用户库恢复，不推进 M5 或代签完整人工体验。

## 实现结果

设置与数据现在可预览、确认恢复，默认取消的系统确认框展示所见文件及摘要。确认后只使用保留的校验副本，一次性凭据和哈希防止旧确认或副本变化。恢复前先沿用关闭保存握手确认草稿与已经发起的显示保存，暂停并排空业务请求，生成独立保护性一致性备份；保护失败返回窗口，不移动原库。

全部连接确认关闭后在应用固定目录执行文件事务：刷写 prepared 记录、保留原主文件与伴随文件、安装及再校验、刷写 committed、清理并重启。失败回退原文件；回退失败保留现场退出。启动先处理未完成事务，坏记录、原件缺失或未知现场停止，不能误建空库。保护性备份可直接从当前 backups 目录选择恢复，旧保护文件保持，另生成新保护文件。

12 个生产/构建与 9 个测试代码文件逐文件两轮复查；实质修改重复复查。计划书、依赖/锁文件、正式 SQL 结构与迁移、原草稿控制器等 8 个关键范围文件保持，正式结构 6。调用链和状态规则见[恢复架构](architecture/M4恢复执行与回退.md)，详细复查见[记录](代码复查记录.md)。

## 自动化启动提示与未验证项

用户报告自动测试时出现“无法启动”。独立诊断复现 firstWindow 后过早 app.exit 造成页面 ERR_FAILED 与相同提示，等待 load 后正常启动记录且无错误日志/提示；已经调整测试收尾，未屏蔽生产启动异常。详见[复现](evidence/m4b/startup-abort-diagnostic.json)与[修正后诊断](evidence/m4b/startup-cleanup-verified.json)。这项诊断不等同于学习库损坏或所有未知输入问题已修复。

系统选择/确认是明确替身。真实重启、独立进程重开、进程中断、合成伴随字节回退分别记录；没有真实断电、所有真实 WAL/外部程序锁定的完整验证。没有操作默认正式/开发学习库，没有生成新 NSIS。M3/M4 完整人工体验、真实原生恢复确认、系统 DPI、外部剪贴板/浏览器、大图、正式题库及 M5 安装升级/离线/性能仍待验；历史键盘偏移、额外字符及 Alt+F4 原因保持未知。
