# M2 第一批：顺序练习与保存事务

日期：2026-10-20。接续 M1 第五批，先实现主进程内部服务和持久化，不接练习窗口，也不提前实现 M3 搜索、随机、收藏交互或历史查询。

## 前置证据与范围

计划书 M1 的六项软件条件已有证据：文字/代码/表格/三图及来源移动由第五批真实窗口验证；伪标题由 AST 测试验证；整批失败、幂等和更新保留独立状态/旧版本引用由第四、五批数据库场景验证。正式题库技术内容审阅、原生对话框人工交互和最终真实使用验收仍未通过，不由本轮推断完成。

本批两个结果：建立可重开的固定顺序练习；建立草稿/揭晓/自评/推进的原子保存服务。输入仍通过内部服务，不开放新的预加载能力。正常 UI 保存节奏、500ms 自动保存提示、退出前提交待保存输入、代码高亮/复制、图片放大留待下一批窗口实现。

## 行为契约

- 仅选活动题目，按专题名称、专题 ID、文件内顺序与题目行 ID 确定顺序；可选单个专题或全部，数量 10/20/50/全部，默认由未来界面选择 20。不足取全部，无匹配时不创建空会话。
- 队列同时固定内容版本和开始时的标题、专题名称、标签、难度。导入更新或归档不会替换本轮内容。新轮创建新的作答行，草稿为空、答案隐藏、无自评，不复制旧轮状态。
- 数据库最多一个活动会话；已有活动会话时不自动结束。明确提供原会话游标后，才可在同一事务中结束旧轮并建立新轮；无匹配或游标已变则旧轮保持。
- 草稿按会话和队列位置保存 UTF-8 纯文本与递增修订号。旧修订拒绝，相同修订/相同内容只确认，相同修订/不同内容冲突。单题草稿上限 1MiB，超过明确拒绝、不截断；后续窗口必须保留输入并提示。
- 揭晓、切题、自评和结束都携带当前草稿，在同一事务中先确认保存，再执行状态变化；保存失败不得推进。空输入可揭晓。揭晓前读取结果没有答案字段，首次揭晓时间不被重试或返回后再次揭晓改写。
- 自评仅在揭晓后接受“不会/不熟/掌握”；自评与推进同一事务，收藏不被覆盖。同轮返回修改只更新该行，新轮另建历史。最新自评仍引用实际作答版本，不把旧版自评标成新版本状态。
- “暂不评价”不创建自评，也不清除原已有自评；“跳过”仅用于未揭晓题，单独记时间，不自动记为不会。“上一题”保留本轮草稿和揭晓；“下一题”用于已揭晓题。最后一题推进后结束本轮。
- 会话游标由会话 ID、位置和会话修订组成；变化操作带 UUID 请求 ID。相同 ID/相同请求返回原回执，相同 ID/不同内容拒绝；不同请求的旧游标也拒绝，防止重复点击推进多题。回执只确认原操作，读取当前状态使用单独读方法。
- 回执与业务变更同一事务。写入抛错后核对持久化回执或草稿：确认已提交则返回成功，确认未提交则可重试；无法判断则阻止该服务实例继续写入，要求重启核对，不能声称数据未变。
- 只统计已揭晓、自评/各等级、揭晓未评价，以及仍未揭晓的跳过题，不提供系统正确率。
- 数据库升级到结构 3，v1/v2 升级前一致性备份并校验；失败保留旧库。所有测试显式临时目录，不读写默认学习库。

## 可重复验收

1. 严格请求/输出、草稿 UTF-8 限额与修订、空输入、非法游标/旧请求/冲突。
2. 真 SQLite 验证固定/无重复队列、无空会话、单活动会话、显式替换、结束/重开、新轮默认状态。
3. 真 SQLite 验证揭晓前无答案、首次时间、同轮自评更新、自评/位置原子性、跳过/未评价与统计分离。
4. 触发器中途失败整笔回滚；提交后响应异常可核实、核实不可用时停写；同请求重试不重复推进。
5. 原题库更新/归档后，本轮仍固定旧内容，旧版本作答和图片引用保留；新轮采用新版本。
6. v1/v2→v3 升级与一致性备份、备份失败/DDL 回滚，以及原有 19 项桌面回归；开发 Electron 和 Windows 解包程序分别执行。
