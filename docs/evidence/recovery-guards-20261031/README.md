## 行为与保护策略

1. 备份校验对全部轮次检查非空、唯一连续零起点队列；活动和提前结束轮位置小于题数，完成轮位置等于题数。异常备份拒绝，不补题、不修正位置。
2. 启动先将原库及伴随文件复制到本次私有暂存，在副本上校验标识、版本、完整性、外键和启动列。检出故障则不让 SQLite 打开原件，避免失败打开也处理原 WAL/SHM。无主库但有伴随文件、或空库仍有伴随文件时不初始化空库。
3. 启动库打不开时仍提供备份预览与明确恢复；不打开故障原件为业务连接。确认后保留 `backups/before-recovery-*` 原始文件副本及哈希清单，同步落盘，保护失败不替换，原件变化不替换。该目录是故障现场，不冒充健康 SQLite 备份。
4. 原恢复事务继续承担连接关闭、原件移走、候选安装、安装校验、失败回退与提交后清理；故障模式沿同一链路。未知恢复事务仍阻断启动。正常健康库恢复继续使用 SQLite 一致性保护备份。
5. 主导航在笔记/待办待保存或上次保存失败时可触发统一保存守卫。失败保留输入、页面和位置，成功才离开；守卫执行及其他业务忙态仍锁住导航。

## 最近筛选性能测量与决定

测试 [recency-performance.spec.ts](../../../tests/e2e/recency-performance.spec.ts) 在独立 TEMP 生成5000题及0、10万、50万练习项。四等分题目分别为从未揭晓、2天、14天、60天前揭晓；所有查询走生产列表 IPC。测试断言不限/未练/7天/30天的总数、最久优先首题，并保留每组预热一次后的七次耗时；不是依据 SQL 文本推定性能。

原始首轮见 [recency-performance.json](recency-performance.json)、`performance-01.json`。最终源码在 `performance-final-02.json` 另测，1/1通过；提取原始附加数据见 [recency-performance-final-02.json](recency-performance-final-02.json)。不以改写原始数据合并两个样本。测量包含 IPC/返回解析开销，采用固定分页第一页和生成分布，不能外推到所有题库、分页或真实用户历史。

最终复测的暖查询中位数如下（毫秒，每组7次）：

| 历史项 | 7天未练/默认顺序 | 7天未练/最久优先 |
| --- | --- | --- |
| 100000 | 87.33 | 118.82 |
| 500000 | 397.51 | 565.42 |

50万历史下普通不限/默认列表为11.46ms；最慢组七次的最大值569.57ms。最终数据库130928640字节（约124.86MiB），实际关闭并重开（含Electron启动、私有副本检查和窗口就绪）2069.63ms，不能把该总时长单独归因为复制或查询。首轮同场景中位579.47ms/最大588.23ms及重开2042.42ms仍原样保留。

本轮决定保留公共筛选 SQL。测量确认高级最近筛选随历史增长存在成本，但普通默认列表仍快，尚无实际用户卡顿证据。合并查询需同时保护列表、计数、条件建轮、方案与配额、未知日期及旧版本语义；本轮将该项转为有原始数据的优化候选，不把重复子查询本身判作已确认故障。
