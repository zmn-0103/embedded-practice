## 实际入口与数据流

主进程内部调用 `await openLibraryImportService(databasePath, reportError)`，取得 `preview(paths, signal?)`、同步 `commit(token)`、`discard(token)` 和异步 `close()`。数据路径必须绝对且由应用决定，当前没有把这个工厂或文件路径交给预加载。

`preview` → 第三批后台准备 → AST 中每题实际使用的引用定义与内容指纹 → 主进程读取题库基线 → 纯变更比较 → 私有快照与随机 UUID 令牌 → 只返回到期时间和摘要。

`commit` → 验证当前令牌 → `BEGIN IMMEDIATE` 事务 → 核对题库修订号 → 重新比较同一快照与同一修订的库 → 图片/题目/版本/归档/回执统一提交。全程不重读 Markdown 或来源图片。

| 文件 | 职责 |
|---|---|
| `src/shared/contracts/library-import.ts` | 令牌、变更摘要、提交回执与服务错误类型 |
| `src/main/services/library/content-fingerprint.ts` | 题干/答案/实际引用定义与图片内容哈希的指纹，在准备线程调用 |
| `src/main/services/library/compare-import.ts` | 稳定身份匹配、变更类别和合计；无文件/数据库副作用 |

| `src/main/database/open-database.ts` | 空库初始化、v1→v2 保护性备份与迁移、连接配置 |
| `src/main/database/repositories/library-repository.ts` | 基线读取、整批事务、回执读取与数据库关联 |

## 身份、版本与摘要

- 稳定身份是 `topic_id + question_id`；数据库内部整数 ID 只用于关联。
- 标题、难度、标签、位置存于题目元数据，变化不新建内容版本。内容版本保留创建当时的标题；后续练习会话如何固定显示元数据，需要在对应阶段落实。
- 指纹以结构化 JSON 计算 SHA-256，包含题干、答案、实际使用的链接/图片定义和图片绑定哈希，不包含文件路径、行号、专题名称和题目元数据。
- 比较时只把 CRLF 统一为 LF，不去掉缩进、行尾空格或其他正文内容；保存的版本正文仍是解析器保留的原文本。引用定义若本身位于正文内，其原始文本也属于正文。
- 新增、更新、元数据、不变、归档、恢复为互斥题目类别；`newVersions` 是额外维度，恢复且内容变化时计入恢复和新版本数。
- 只处理参与导入的专题。缺失的活动题归档，已经归档且仍缺失的题不重复计数；恢复时复用原行、收藏与旧版本。
- 专题名称或来源信息变化单独标识；相同来源与内容的重复导入不改变题库修订号，但每次新确认仍保留提交回执。同一令牌重复确认不新增回执。

## 令牌与故障

默认 15 分钟有效，最多一个待确认快照；开始新预览就使旧预览失效，即使新准备随后失败。忙碌请求不会替换当前准备。可通过 AbortSignal 取消准备，已准备的快照通过 `discard` 放弃。

到期计时器、显式放弃、新预览和关闭均释放快照；确认成功立即释放正文与图片，只暂留原回执以处理重复确认。返回值使用副本，不将私有快照返回调用方。时钟倒退至创建时间之前也拒绝确认；该机制不是系统时钟可信性的保证。

预览绑定全库题库修订号，其他导入改变库时旧预览返回 `PREVIEW_STALE`，不悄悄改变用户确认的结果。学习状态和启动记录不修改该修订号。进程重启后令牌失效，需重新预览。

题目、版本、图片、修订号和回执在同一事务。确认抛错时先读取持久化回执：有回执则返回成功；确认无回执且连接已退出事务时保留快照供明确重试；回执读取失败或事务未结束时释放令牌并停止本次写入，提示重启。诊断回调抛错不能覆盖业务结果。业务结果没有原始异常或堆栈。

## 数据模型与升级

结构版本为 2，应用标识仍为 `0x45505231`。

| 表 | 本批用途 |
|---|---|
| `app_startup` | 保留 M0 启动记录，读取接口不变 |
| `library_meta` | 单行题库修订号 |
| `topics` / `questions` | 专题、稳定题目身份、当前元数据与归档状态 |
| `question_versions` | 不可变正文、定义、图片 URL→哈希绑定和内容指纹 |
| `image_resources` / `version_images` | 按哈希去重的图片 BLOB、版本引用；不清理旧引用 |
| `question_user_state` | 独立收藏与最近自评关联，为后续服务保留；本批没有收藏/自评窗口接口 |
| `import_receipts` | 与提交同事务的结果摘要；不是公开令牌查询接口 |

当前版本与最近自评通过组合外键保证属于同一题。最新掌握状态应比较 `last_rated_version_id` 与 `current_version_id`，导入不把旧自评挪到新版本。数据库集成测试使用真实状态行，以及明确标为测试专用的历史外键引用夹具；不代表练习/作答/历史查询功能已实现。

旧 M0 库先通过 `database.backup` 写入数据目录 `backups/pre-migration-v1-UUID.sqlite3`，只读检查完整性、应用标识及旧结构版本后再执行迁移。备份创建或验证失败时不执行 DDL；DDL 和 `user_version` 更新同事务，失败保留旧结构和备份。空库直接在事务中初始化结构 2。未知、损坏及更新版本库继续拒绝，不清空重建。

保护性备份需要额外磁盘空间。本批只实现 v1→v2；完整备份恢复、通用迁移管理仍属 M4。若迁移成功后的连接配置等步骤失败，已生成的旧库备份仍保留，不能把所有启动失败都解释成未发生迁移。
