## 三、判断题（49～60题）

判断正确或错误。

**49.** I2C 设备输出逻辑高电平时，通常通过开漏晶体管主动将 SDA 推到高电平。

**50.** I2C 可以利用设备地址，在一组共享的 SCL/SDA 信号线上区分不同目标设备。

**51.** EEPROM 对写入数据返回 ACK，就一定说明该数据已经成功保存到非易失性存储单元。

**52.** 若 I2C 目标设备的 7 位地址为 0x68，则在 STM32F10x 标准外设库的常规 7 位寻址中，可以将 0xD0 作为 `I2C_Send7bitAddress()` 的地址参数，并通过方向参数选择读写。

**53.** `I2C_CheckEvent()` 仅检查一个普通软件变量，不会涉及硬件寄存器读取副作用。

**54.** `I2C_OwnAddress1` 用于指定当前 STM32 主机准备访问的传感器地址。

**55.** TXE = 1 就一定代表当前最后一个字节已经完整发送到 I2C 总线上。

**56.** 可靠的 I2C 驱动应该考虑超时和错误退出机制。

**57.** STM32F103 主接收模式下，RXNE 和 BTF 的含义完全相同。

**58.** STM32F103 接收两个字节时，可以完全忽略 POS、ACK 与 ADDR 清除之间的时序关系。

**59.** STM32F103 存在已知的 I2C 硬件限制，在特定情况下，SCL/SDA 实际为空闲高电平，但 BUSY 仍可能异常保持置位。

**60.** 在普通 I2C 多字节读取中，控制器通常对中间字节发送 ACK，对最后一个字节发送 NACK。

### 70. 连续接收三个字节失败

3. 读取一个字节。
4. 重复以上接收操作，直到读取 3 个字节。
5. 最后产生 STOP。

请回答：

（1）该处理思路忽略了 STM32F103 的什么特殊要求？\
（2）最后三个字节为什么需要关注 BTF？\
（3）ACK 应该在什么时候关闭？\
（4）为什么不能在严格的关键时序之间随意设置断点？

### 71. I2C 总线一直 BUSY

### 72. 读取传感器 16 位数据错误

- 高字节寄存器地址：0x20。

### 需要重点理解的题目

**第 18、19 题：TXE 与 BTF 的区别**

TXE 置位只表示发送数据寄存器为空。

当前数据可能已经进入发送移位寄存器，但仍在总线上传输。

BTF 可以帮助判断末尾字节是否已经完成传输。

主发送模式结束时，通常需要等待 BTF 再请求 STOP。

**第 20 题：I2C 地址格式**

以设备 7 位地址 0x50 为例：

- 7 位地址：0x50。
- 左移后的地址参数：0xA0。
- 写方向地址字节：0xA0。
- 读方向地址字节：0xA1。

STM32F10x 标准库 `I2C_Send7bitAddress()` 只调整地址最低位，不会替调用者完成原始 7 位地址的左移。

**第 23～25 题：STM32F1 接收特殊性**

接收 1 字节、2 字节以及 3 字节以上时，必须采用不同的结束控制。

原因是 ACK、POS、ADDR、BTF 和 STOP 的时序关系不同。

不能机械地套用完全相同的接收循环。

**41. 答案：A、B、D**

解析：

I2C 通常使用开漏结构和有效上拉。不同设备之间还需要满足共同的电平参考要求，常见电路需要共地。

SDA 不能按照普通推挽方式直接与多个 I2C 设备共同驱动。

**42. 答案：A、B、C**

解析：

START 和 STOP 通过 SCL 高电平期间 SDA 的特定变化识别。

普通数据传输时，SDA 通常在 SCL 低电平期间改变，并在 SCL 高电平时保持稳定。

**43. 答案：A、B、C**

解析：

I2C1 使用 APB1 时钟，GPIOB 使用 APB2 时钟。

初始化前需要使能相应时钟，GPIO 通常配置为复用开漏输出。

**44. 答案：A、B、C**

解析：

主发送时需要关注 SB、ADDR、TXE、BTF 等状态。

RXNE 属于接收数据寄存器非空状态，不是典型主发送数据阶段需要等待的标志。

**45. 答案：A、B、C**

解析：

STM32F1 双字节接收需要正确协调 POS、ACK、ADDR 和 BTF。

不能忽略 ADDR 的清除时序。

**46. 答案：A、B、C**

解析：

AF、BERR 分别与应答失败和总线错误有关。

BUSY 是总线状态，不是独立的错误标志。

普通 I2C 驱动还需要自行设计软件超时，不能依赖硬件 TIMEOUT 标志处理所有等待问题。

**47. 答案：A、B、C**

解析：

逻辑分析仪侧重协议解码。

示波器侧重模拟电压和信号质量。

STM32F1 的部分 I2C 标志具有特殊清除顺序，调试器的寄存器读取可能对状态产生副作用。

**48. 答案：A、B、D**

解析：

可靠的通信层应当提供错误返回和超时处理。

器件驱动需要负责具体器件的命令、寄存器格式及特殊规则。

不同器件不一定采用相同的寄存器协议。

## 第四部分：简答题参考答案

### 61. START、STOP 及数据稳定性

START：

SCL 为高电平时，SDA 从高电平变为低电平。

STOP：

SCL 为高电平时，SDA 从低电平变为高电平。

数据稳定性：

普通数据传输期间，接收方需要在 SCL 高电平期间读取稳定的数据位。

如果普通数据在 SCL 高电平期间随意变化，可能被识别为特殊的 START 或 STOP 条件，或者造成采样错误。

因此，普通数据通常在 SCL 低电平时改变，在高电平期间保持稳定。

### 62. ACK/NACK 由谁产生？

ACK/NACK 由当前字节的接收方产生。

情况一：STM32 主发送设备地址。

设备地址由 STM32 发送，目标设备接收，因此由目标设备产生 ACK/NACK。

情况二：STM32 主发送数据。

STM32 发送数据，目标设备接收，因此由目标设备产生 ACK/NACK。

情况三：STM32 主接收数据。

目标设备发送数据，STM32 接收，因此由 STM32 产生 ACK/NACK。

如果 STM32 不再需要后续数据，通常对最后一个字节产生 NACK。

### 63. 设备地址计算

已知：

7 位设备地址为 0x29。

写方向地址字节：

`0x29 << 1 = 0x52`

读方向地址字节：

`0x52 | 0x01 = 0x53`

最终答案：

- 写方向：0x52。
- 读方向：0x53。

标准外设库不会自动左移原始 7 位地址，因此调用时必须使用符合其参数要求的地址格式。

### 64. I2C_InitTypeDef 六个主要参数

1. I2C_ClockSpeed：目标 SCL 通信频率。
2. I2C_Mode：I2C/SMBus 模式。
3. I2C_DutyCycle：快速模式占空比。
4. I2C_OwnAddress1：STM32 自身地址。
5. I2C_Ack：ACK 配置。
6. I2C_AcknowledgedAddress：本机地址识别格式。

本机地址主要用于 STM32 作为目标设备时的地址匹配。

目标设备地址是主机在通信过程中发送的对方地址。

二者不是同一个概念。

### 65. 状态标志解释

SB：

START 条件已经产生。

ADDR：

地址匹配或地址阶段完成，对 STM32 主机而言通常对应目标设备应答后的状态。

TXE：

发送数据寄存器为空。

RXNE：

接收数据寄存器中有未读取的数据。

BTF：

字节传输完成，具体含义需要结合发送或接收模式判断。

TXE 与 BTF 的区别：

TXE 表示 DR 为空，但发送移位寄存器可能仍在传输。

主发送模式下，BTF 可以表示 DR 和移位寄存器均为空，末尾字节已完成传输。

### 66. 接收不同长度数据的区别

**接收 1 字节：**

需要及时关闭 ACK，正确清除 ADDR，提前安排 STOP，等待 RXNE 后读取数据。

**接收 2 字节：**

需要配置 POS，正确处理 ACK 与 ADDR 的顺序，等待 BTF，再安排 STOP 并取出两个字节。

**接收 3 字节及以上：**

前面的数据可以按规定状态正常读取。

当剩余三个字节时，需特别处理：

1. 等待 BTF。
2. 关闭 ACK。
3. 读取倒数第三字节。
4. 按规定等待后续 BTF。
5. 请求 STOP。
6. 读取倒数第二字节。
7. 等待 RXNE。
8. 读取最后一个字节。

关键时序应参考 ST AN2824，不应在需要及时处理的操作之间加入任意延时。

### 67. 读取器件内部寄存器

假设目标设备具有 8 位寄存器地址，使用常见的组合读取协议。

典型流程：

1. START。
2. 发送设备地址及写方向。
3. 等待 ACK。
4. 发送内部寄存器地址。
5. 等待 ACK。
6. 产生重复 START。
7. 发送相同设备地址及读方向。
8. 等待 ACK。
9. 接收寄存器数据。
10. 对最后一个字节产生 NACK。
11. 产生 STOP。

重复 START 的作用：

在不先释放总线的情况下，开始新的地址和读写方向阶段。

通过这种方式，STM32 可以先指定目标寄存器，再切换为读方向获取数据。

实际访问流程需要符合目标器件的数据手册。

### 68. I2C 驱动分层

**应用层：**

实现具体业务功能，如读取温度、保存参数。

**器件驱动层：**

处理传感器或 EEPROM 的寄存器地址、命令、数据格式和特殊规则。

**通用 I2C 通信层：**

处理 START、地址发送、数据发送、数据接收、STOP、错误处理与超时。

**硬件层：**

配置 STM32 的 RCC、GPIO、I2C 外设及标准外设库相关接口。

分层的主要好处：

- 减少重复代码。
- 便于更换器件。
- 方便故障定位。
- 提高驱动可维护性。
- 使总线通信逻辑可以被多个器件复用。

## 第五部分：综合分析题参考答案

### 69. 地址发送后没有 ACK

**（1）可能存在什么错误？**

将未经左移的 7 位地址 0x68 直接传给标准外设库。

STM32F10x 标准外设库不会自动将原始 7 位地址左移。

**（2）正确地址如何计算？**

7 位地址：0x68。

左移：

`0x68 << 1 = 0xD0`

向 `I2C_Send7bitAddress()` 传入符合标准库格式的 0xD0，再通过方向参数指定写方向。

**（3）修改后仍然没有 ACK，需要检查什么？**

检查：

- 传感器是否供电。
- GND 是否共地。
- SDA/SCL 是否接反。
- GPIO 是否配置为正确模式。
- 是否存在有效上拉。
- I2C1 是否正确初始化。
- 目标设备是否处于可应答状态。
- 是否实际产生 START。
- AF 等错误标志是否置位。
- 逻辑分析仪显示的设备地址是否正确。

**（4）如何避免卡死？**

对 EV6 等待设置合理超时。

同时检查 AF、BERR、ARLO 等错误状态。

如果发生错误或超时，应退出当前等待，根据外设和总线状态执行合适的终止或恢复处理，而不是无限循环。

### 70. 连续接收三个字节失败

**（1）忽略了什么？**

忽略了 STM32F103 在接收最后几个字节时，必须精确控制 ACK、BTF、STOP 和 DR 读取顺序的要求。

**（2）为什么关注 BTF？**

当 DR 和移位寄存器中都有待处理数据时，BTF 可以置位。

在允许时钟延展的情况下，外设能够暂停后续传输，为软件配置结束时序提供机会。

**（3）ACK 什么时候关闭？**

根据 AN2824 的三字节末尾处理流程：

当剩余三个字节并等待到 BTF 后，关闭 ACK，然后读取倒数第三个字节。

随后按规定等待后续 BTF，再请求 STOP、读取倒数第二个字节，最后等待 RXNE 并读取末字节。

这样可以确保最后一个字节获得 NACK。

**（4）为什么不能随意设置断点？**

因为 CPU 暂停后，I2C 外设和目标设备可能继续按照硬件时序运行。

如果关键操作延迟，可能破坏 ACK/NACK 或 STOP 的产生时机。

应优先通过连续运行、状态记录和逻辑分析仪观察协议。

### 71. BUSY 一直为 1

**（1）是否一定说明传感器损坏？**

不能。

SDA 和 SCL 均为高电平，只能说明测量时物理总线没有明显被拉低。

还需要检查 MCU 的 I2C 内部状态。

**（2）查阅哪个文件？**

ST ES0340：

STM32F101xC/D/E 和 STM32F103xC/D/E 芯片勘误表。

其中记录了 I2C 模拟滤波器可能导致 BUSY 错误置位的问题。

**（3）为什么软件复位不一定有效？**

因为该异常可能涉及 I2C 模拟滤波器内部的状态，而不是单纯的软件控制寄存器配置错误。

因此，直接设置 SWRST 不一定能够恢复正常。

**（4）恢复原则是什么？**

首先排除真实总线占用、线路错误和其他硬件问题。

如果符合芯片勘误描述的条件，应遵循 ES0340 提供的恢复过程，通过受控 GPIO 电平变化恢复相关内部状态，再重新配置 I2C 外设。

不能无条件地对所有 BUSY 故障采用同一种复位方式。

### 72. 16 位数据组合

**（1）组合结果是多少？**

高字节：0x01。

低字节：0xF4。

计算：

`(0x01 << 8) | 0xF4`

结果：

`0x01F4`

**（2）十进制是多少？**

`0x01F4 = 500`

**（3）结果错误应检查什么？**

- 高低字节是否交换。
- 寄存器地址是否正确。
- 是否支持连续读取。
- 是否需要启用地址自动递增。
- 是否使用正确的数据类型。
- 数据是否有符号。
- 是否需要按照器件手册进行缩放或转换。
- 多字节接收时序是否正确。

**（4）地址 ACK 是否证明数据一定正确？**

不能。

地址获得 ACK 只能说明该通信阶段得到应答。

寄存器访问、数据顺序、数据解释和器件状态仍然可能存在错误。

### 73. EEPROM 跨页写入

**（1）涉及哪两个页面？**

假设每页为 64 字节。

第一个页面范围：

`0x0000～0x003F`

第二个页面范围：

`0x0040～0x007F`

从 0x003E 开始写入四个字节，涉及：

- 0x003E
- 0x003F
- 0x0040
- 0x0041

因此跨越两个页面。

**（2）为什么不能直接执行普通的 4 字节页写入？**

24LC256 的页写入受页面边界限制。

如果直接跨越页面边界继续发送数据，内部地址可能在当前页面范围内回绕，从而覆盖不希望修改的数据。

**（3）怎样拆分？**

第一笔：

从 0x003E 开始写入两个字节。

对应地址：

- 0x003E
- 0x003F

第二笔：

从 0x0040 开始写入另外两个字节。

对应地址：

- 0x0040
- 0x0041

两笔操作分别满足页面边界要求。

**（4）如何确认内部写周期结束？**

可以使用 EEPROM 数据手册规定的 ACK Polling 方法。

在上一笔写入事务结束后，按照器件要求尝试寻址，直到设备恢复应答。

轮询还需要设置合理超时。

只有确认上一笔内部写周期已经完成，才能可靠地开始后续写入。
