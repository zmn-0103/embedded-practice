# M1 第一批：题库文件与结构解析

日期：2026-10-20。

## 本次目标

1. 将用户提供的 GPIO 自测题整理为完整 V1 专题文件，保留原题、原答案与 78 个稳定身份，标明硬件及实验条件。
2. 实现不访问文件系统或数据库的 Markdown 结构解析：返回完整专题与题目，或带文件名、行列和原因的错误集合。

## 解析行为

- 使用 unified / remark 语法树识别文件头、二级题目标题与固定三级分区，不按字符串中的 `##` 切分。
- 支持中文、UTF-8 BOM、CRLF/LF、代码块、表格、列表和图片引用；保留题干与答案的原始 Markdown 正文。
- 校验版本、专题字段、题目 ID、重复 ID、元数据、难度、分区数量、顺序、非空正文和标题层级。
- 代码块内的伪题目、伪分区和元数据只作为代码保留；题干里的“标签/难度”不改写元数据。
- 拒绝原始 HTML；图片只做语法及引用路径的静态检查，收集引用位置供下一步资源服务处理。
- 单文件上限 20MiB；文件内题目超过单批 10,000 题的上限时明确报错。
- 任何结构错误都不返回“部分成功”的题库；解析过程不写入来源文件、正式题库或数据库。

## 本次验证

- 对 78 道原题与原答案逐项验证对应关系，检查章节、ID、正文与补充条件。
- 正常夹具覆盖代码伪标题、表格、图片、嵌套列表、BOM 与不同换行。
- 错误夹具覆盖无效 YAML、未知版本、缺字段、重复 ID、无效难度、缺分区、空正文、错误标题及不支持的图片引用。
- 每个代码文件分别进行 Bug 检查与优化检查，再继续下一个文件，结论记录在代码复查记录中。
- 执行类型、格式、单元与现有桌面流程回归；只有实际通过的检查才进入验收记录。

## 后续范围

真实图片存在性、类型/大小和规范化路径校验，批量解析工作线程，预览令牌、事务提交、更新归档、图片入库、模板导出和界面接入属于 M1 后续工作。本批不修改数据库结构，不提前实现 M2 的作答或揭晓流程，也不把第一批完成描述为 M1 整阶段通过。
