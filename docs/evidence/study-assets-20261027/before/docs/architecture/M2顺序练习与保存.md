入口 `await openPracticeService(databasePath, reportError)` 构建为 `out/main/practice.js`；数据库路径只由主进程提供。第一批仅由内部测试调用，第二批已由主入口创建并接入练习窗口，没有生产测试接口。内部测试通过 Electron 加载固定入口，不使用系统 Node 加载 Electron ABI 的原生模块。

| 方法 | 输入与输出 |
|---|---|
| `read` | `{sessionId: null}` 找活动轮；指定 UUID 读该轮当前视图/结束摘要；无活动轮为 null |
| `start` | UUID 请求 ID、专题或全部、10/20/50/全部数量、原活动游标或 null；返回新轮回执 |
| `saveDraft` | 会话 ID、队列位置、`draft: {revision, text}`；返回已保存修订确认 |
| `reveal` | 请求 ID、当前游标、草稿；保存草稿并记录首次揭晓，返回回执 |
| `rateAndAdvance` | 同上，另传“不会/不熟/掌握”或 null；保存自评和推进同事务 |
| `navigate` | 同上，另传 previous/next/skip；保留本轮已揭晓/草稿，原子切题 |
| `end` | 请求 ID、游标、草稿；保存后结束本轮，记录保留 |
| `close` | 同步释放独立连接，可重复；之后所有方法返回 SERVICE_CLOSED |

所有业务方法返回 `{ok, value}` 或 `{ok:false, error:{code,message}}`，不返回 SQL 或错误堆栈。输入为严格 Schema；草稿上限 1MiB UTF-8，保留换行/空白，拒绝超限和无法无损编码的孤立代理项，不截断。

## 固定队列与版本

选题只取活动题，按专题标题、专题 ID、文件内位置、题目行 ID 排序；不足所选数量时取全部，不创建空轮。队列作答行通过组合外键保证版本属于该题，按会话/题目唯一，固定开始时的标题、专题名称、标签、难度及版本。

`practice_sessions` 的部分唯一索引保证最多一个 active。已有活动轮且未明确提供原游标时返回 ACTIVE_SESSION_EXISTS；明确替换时，先验证旧游标并选出非空队列，再在同一事务结束旧轮、创建新轮。无匹配或旧轮已变均保持原状态。

`practice_items` 是真实本轮作答记录，保存草稿修订、首次揭晓、自评/时间、跳过时间。同轮修改更新原行，新轮创建新行且默认空输入/隐藏/无自评。导入更新、标题变化、缺题归档不改本轮队列；旧图片由旧版本引用保留。历史记录仍无列表/查询页面，本批测试用实际作答行核对保留。

## 保存、切题与统计

草稿修订按会话和位置比较：低于已保存值为 DRAFT_STALE；相同值且同内容只确认；相同值但不同内容为 DRAFT_CONFLICT；更高值写入。会话结束后不再保存迟到草稿。

揭晓、切题、自评、结束都携带草稿，保存与状态变化同事务。即使游标有效，只要草稿过期，也不能揭晓、跳过、结束或自评推进。保存失败回滚整个操作，不丢弃原已保存草稿；第二批窗口控制器负责继续保留尚未保存的输入。

游标由会话 ID、位置和会话修订组成。变化操作只有当前 active 游标可接受，每次增加修订；不同 UUID 的重复点击也会被旧游标拦住。揭晓不移动位置，首次揭晓时间保留。未揭晓时的读取 SQL 不选择答案列，返回对象也没有答案字段；揭晓后才另读固定版本答案。

自评仅在揭晓后可用，修改本轮行与更新独立用户状态、推进位置同事务。用户状态只更新最近自评及其实际版本，保留收藏；旧版本自评不会被挪到新版本。“暂不评价”不新建或清除已有自评；未揭晓的跳过另记时间，已揭晓题用下一题/暂不评价。上一题保留本轮揭晓和草稿；末题推进后 status=finished、position=total，返回摘要而无题目正文。

统计含已揭晓、自评、揭晓未评价、三档自评数量和仍未揭晓的跳过数。跳过后返回揭晓，不再计入“仍未揭晓的跳过”，原跳过时间保留。没有正确率或把未评价计为不会的规则。

## 幂等与结果不明

请求回执与全部变更同事务。哈希覆盖操作类型和标准校验后的完整输入；同 UUID/同输入返回原回执，同 UUID/不同输入拒绝。回执只含原操作确认和游标，不复制整篇题干、答案或草稿；它可能早于当前状态，客户端应另读当前视图。

事务抛错后，仓储先检查连接已离开事务，再读对应回执；草稿则比较已持久化的修订和正文。已提交返回原结果；确认未提交才返回 WRITE_FAILED 并允许同请求重试。无法核实则 OUTCOME_UNKNOWN，实例停止后续写入，须重启重新读取；不根据抛错假定数据库没变。仓储拒绝在外层事务内保存，避免仅释放保存点就宣称持久化成功。

测试在实际提交成功后包装一次响应异常，验证回执/草稿核实；另在提交后关闭测试连接，验证结果不明停写与重开确认。包装不修改供应商或生产代码，区别于真实系统断电。

## 结构升级与窗口接入

结构 3 新增三张练习表和索引，M1 表不重建。空库直接初始化；v1/v2 先使用 SQLite backup 写入 `backups/pre-migration-v<旧版本>-UUID.sqlite3`，只读校验完整性、应用标识与旧版本，再在单个事务迁移。v1 先加入 M1 表再加入练习表，v2 只增加练习表；备份期间身份/版本变化会停止。备份失败不改旧库，DDL 冲突回滚旧版本并保留保护性备份。

当前版本会把受支持旧库升级到 3；旧 M0 NSIS 产物不支持新结构，继续使用当前解包程序。完整备份恢复、通用迁移框架与安装升级交付仍属后续阶段。

第二批已接固定练习 IPC、页面、500ms 草稿保存与状态、切题/揭晓/返回首页/正常退出前刷新待保存输入、失败保留及重试，并实现代码高亮/复制和图片放大，见[窗口说明](M2练习窗口与保存.md)。第一批内部数据库证据与第二批窗口证据分别记录，不能代替输入法、系统强制关机或性能验收。
