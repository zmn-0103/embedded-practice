## 已确认问题与修改范围

在当前 Windows 解包程序中，通过真实键盘 Tab 从“我的答案”折叠标题进入输入框，输入位置被底部悬浮操作区遮住。继续键入测试文字后，原生无障碍树显示内容已改变、保存状态为已保存，但视口内仍看不到输入行；截图与原始观察保存到 `docs/evidence/m2d/`。

只允许调整练习展示组件的输入焦点可见性，并补充现有 Electron 测试和必要文档。不修改控制器、自动保存时序、退出握手、数据库、IPC、依赖或原题库。

输入框获得焦点时，如果输入文字将被操作区遮住，应将输入框顶部移到可见区域；已经可读的输入位置保持。草稿和保存状态更新不重新定位，不改变选择、内容或揭晓状态。

## 验收条件与边界

1. 先用未修源码的构建运行新增场景，记录 Tab 聚焦后输入行被遮挡的失败证据。
2. 在 Electron 页面缩放 100%/125%/150% 下，模拟实际阅读滚动位置，用 Tab 进入输入框；第一行的实际命中元素应是输入框，不能是悬浮操作区。输入、自动保存和 Shift+Tab 返回后再进入均可用。
3. 已可见的输入框再次聚焦不移动页面；同题自动保存保持滚动和焦点，既有图片预览、防重复操作、保存失败和退出回归保持。
4. 类型/格式、单元、完整开发构建和重新生成的 Windows 解包程序分别验证；保留失败报告，不覆盖旧 M0 NSIS。
5. 原生 Windows 自动化另记真实文件框、中文拼音候选/选词、键盘、系统剪贴板和正常关闭重开。它与 Electron 自动化、人工验收分别认定；只对实际执行的操作作结论，不将页面缩放写成系统 DPI，也不替用户审阅正式题库。
