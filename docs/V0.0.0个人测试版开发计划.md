# V0.0.0 个人测试版开发计划

> 文档类型：阶段历史。本文保留该批次的原始需求、设计或验收范围；其中“当前”“未实现”和版本号仅指当时，不覆盖[现行文档索引](README.md#当前业务规则)与[当前交付](当前试用版本交付说明.md)。原始失败和待验结论保持。


2026-10-24，用户授权开始开发、本地分批提交及交付，不推送或在线发布。下文保存本次用户计划原文；实际进度与验收分别进入开发记录和验收记录。

**接下来的开发目标确定为：交付“V0.0.0 个人测试版”，完整处理你提供的全部自测题，完成分类、难度评定和内容优化，整理项目后提交，再根据你的实际使用反馈迭代。**

这一阶段以现有功能收尾和题库建设为主，暂不增加大功能。现有板块入口、难度显示、练习方案、继续练习、草稿保存和备份恢复继续沿用。

**1. 全量处理原始自测题，不能停留在精选小样**

以目前盘点的 **8 份资料、433 道原题**为基线，逐题处理并记录最终去向。

- 通用知识归入对应的通用板块。
- STM32 专用知识归入 STM32 板块下的对应专题，保留具体系列、库版本等必要条件。
- 外部器件专用知识按内容归入存储、通信等对应专题。
- 重复题允许合并，混合多个独立考点的题允许拆分，保留完整来源关系。
- I2C 第二层缺少参考答案的题，需要补充依据并组织答案。
- 无法确认的技术结论明确标记待核实，不编造确定答案。

**验收标准：433 道原题全部能追溯到处理结果，没有无说明遗漏。最终题数可以因合并、拆分而变化。**

**2. 建立清晰的板块和专题归属**

按现有“板块 → 专题”两层结构组织，例如：

| 板块 | 专题示例 |
|---|---|
| STM32 | STM32F1 GPIO、UART、SPI、I2C、ADC |
| 通信协议 | UART 通用基础、SPI 通用基础、I2C 通用基础 |
| MCU与外设原理 | GPIO 通用基础、ADC 通用基础 |
| 存储与文件系统 | Flash 原理、具体存储器件专题 |

文件继续放在现有 `question-banks` 下，题目和答案保存在同一专题文件中。程序内归属与文件组织同步核对，不把建立文件夹当成已经完成应用内分类。

**3. 逐题优化内容，统一难度和标签**

每题检查题意、前提、题答对应、技术准确性及解释方式，保留原本的考查目的。

| 难度 | 评定口径 |
|---|---|
| 易／基础 | 单一概念、直接解释或简单推导 |
| 中／进阶 | 多条件、计算步骤、时序或异常分析 |
| 难／综合 | 跨知识点推理、故障定位、设计与取舍 |

答案优先采用“核心结论 → 必要解释 → 适用条件”，根据题目需要补充常见误区和来源。标签表达知识点和题型，避免重复、含糊或泄露答案。

**题目难度与个人掌握程度保持独立。** 后续根据你的反馈调整难度，但不会因为一次答错就自动改为难题。

**4. 对照已有题库，保护题目身份和学习记录**

先核对现有 GPIO 78 题、UART 30 题和通用 10 题与原资料的关系，避免重复建设。

- 同一道题的优化保留已有身份。
- 拆分或形成不同考点时建立新身份，记录对应关系。
- 每次导入提供完整专题快照，不能仅用新增片段覆盖原专题。
- 在独立测试数据中验证首次导入、重复导入、内容更新、分类与难度筛选，以及旧练习记录保护。

**5. 整理项目文件，制作清晰的使用交付目录**

先列出具体清理清单，再处理确认无用的空目录、可重建产物和重复临时文件。

原始资料、来源映射、必要测试证据、失败记录、当前完整程序和个人学习数据保留。被文档引用的截图不能直接删除；历史材料如需归档，要保持可恢复和可追溯。

另外准备一个便于你使用的交付目录，包含：

- 完整测试版程序。
- 本批可导入题库。
- 简短的启动、导入和备份说明。
- 已知问题与反馈记录入口。

**6. 固化 V0.0.0 测试版并验证**

统一应用版本、测试版标识和当前交付说明，使用独立构建编号，重新生成完整程序包。

- 产品版本定位为 **V0.0.0 测试版**。
- 数据库结构按实际实现保留，不随产品版本号重置。
- 保留应用身份与数据路径，确保已有学习数据仍可识别。
- 核对新包启动、导入、练习、保存退出、重开继续和备份恢复。
- 根据实际代码改动运行相应检查，保留原始失败及未验事项。

此前明确跳过的 VMware 安装排障不自行恢复。

**7. 本地提交、交付使用，再按反馈迭代**

按可审查的范围分批提交：现有功能收尾、题库内容、项目整理、测试版版本与交付说明。默认只做本地提交，不自动推送或发布。

交付后，反馈至少记录**构建编号、题目 ID、问题现象、预期结果**。后续处理优先级为：

**数据与保存问题 → 题目答案问题 → 操作阻碍 → 阅读体验 → 新功能。**

整个阶段可以分批开发、逐专题检查，但最终交付范围是**全部原题的处理结果**。程序版本与题库版本分别记录，后续只修改题目时可以单独更新题库。

按照这份开发计划，开始接下来的开发；
