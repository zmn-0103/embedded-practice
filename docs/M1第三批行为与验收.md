# M1 第三批：导入准备工作线程

日期：2026-10-20。本批接续第二批文件与图片快照，完成后台任务及其构建/运行验证；M1 整阶段继续开发。

## 本次行为

- 在 Node 工作线程中执行 Markdown 解析、源文件和图片读取、尺寸检查与哈希计算，不在窗口主线程执行这些准备操作。
- 每个服务实例最多一个活动任务；并发请求明确返回忙碌，结束后可再次准备。服务关闭后不接受新任务。
- 提供取消和 120 秒任务期限；结果、错误、无结果退出、非法消息、超时和取消都只结算一次，等待线程停止后才完成请求。
- 请求及回复有固定协议版本，校验路径与快照结构，不暴露任意脚本路径、SQL 或通用消息入口。回复必须来自对应线程。
- 图片使用可转移的自有字节缓冲区回传；主线程继续保留第二批完整快照语义。失败不返回部分结果，意外错误仅通过内部诊断回调报告。
- 采用现有 electron-vite 工作线程支持，把运行服务与工作入口纳入构建。服务单独导出为主进程内部模块，供下一批 IPC/预览服务调用及本批真实 Electron 测试。

## 验收条件

1. 用受控工作线程替身覆盖忙碌、取消、超时、异常/无结果退出、非法回复、构造失败、停止失败及监听器/计时器清理。
2. 实际构建后在 Electron 主进程调用服务，读取 GPIO 78 题和三种配图示例，检查图片字节/哈希与独立线程身份。
3. 实际验证取消、超时、重复任务、失败后重试与服务关闭；所有写入只在独立测试目录中进行。
4. 对含 ASAR 的 Windows 解包产物重复运行对应场景，区分开发构建、解包程序与安装包。
5. 每个代码/配置文件依次完成 Bug 检查和优化检查；运行结果、失败修正和未验证项另记。

## 边界

本批不添加预览令牌、数据库变更比较、入库事务或窗口入口。工作线程是本地主进程内部组件，渲染进程仍只有原来的状态读取接口。图片检查范围沿用第二批的签名/头部尺寸，不声称完整像素解码。120 秒是任务失败边界，不是性能目标或测量结果。
