## 实际数据流

`prepareImport(绝对路径列表)` → 有界读取 Markdown → 严格 UTF-8 解码 → 第一批 AST 解析 → 专题/题量检查 → 解析图片真实路径 → 有界读取与格式检查 → 内容去重 → 完整批次快照。

选择列表在进入异步读取前复制。来源为 `.md` 普通文件，单文件 20MiB；读取使用只读句柄，检查前后大小、修改/变更时间，`finally` 关闭句柄。UTF-8 BOM 和原始换行保留在快照原文中，纯解析器自行处理 BOM。

任一来源失败即停止当前批次；错误保留文件名、行列、错误码和中文原因，不带部分快照、图片说明、系统堆栈或底层异常对象。底层异常的 cause 只在本地异常内部保留，不进入结果。

## 图片路径与检查范围

以规范化 Markdown 实际位置旁的 `assets` 作为边界。根目录不能是指向其他位置的 junction；子目录或图片链接只有实际目标仍在该 `assets` 内才可读取。访问前后复查真实路径；兄弟目录同前缀不算在目录内。Windows 设备名、非法字符、尾点/尾空格、远程/绝对/越界引用均拒绝。

图片每张限 10MiB，并受批次剩余预算约束。先检查 PNG/JPEG/WebP 签名，再由 image-size 2.0.4 读取类型和正整数尺寸；类型须与引用后缀一致，WebP 的 RIFF 长度须对应实际字节数。该工具只读取格式头部，不证明像素数据完整或图片一定能显示；后续受控显示仍需处理解码失败。

image-size 是纯 JS、MIT 许可依赖，无新增原生图片工具链；版本由 npm 锁定。来源：[维护仓库](https://codeberg.org/image-size/image-size)，许可原文见[image-size-MIT.txt](../licenses/image-size-MIT.txt)。未为本项目另行选择开源许可证。

路径核对与时间检测覆盖静态链接和常规来源变化，不构成针对同权限恶意进程持续替换目录/挂载点的操作系统安全边界，也不承诺来源多个文件在同一个时刻原子读取。

## 计数与字节所有权

Markdown 文件均计入来源大小；不同规范化图片路径各计一次，重复引用同一路径不再次计数。相同图片内容来自不同路径时仍计来源大小，但按 SHA-256 只保留一份资源字节。复用路径缓存时仍核对引用扩展名，避免借别名跳过类型检查。

快照保留原题答、原文、引用定义、资源哈希及自有字节；来源修改或移动不改变返回内容。第四批补充逐题实际引用定义和内容指纹，在线程内计算。预览服务现已私有持有快照，只返回令牌/摘要，并在过期、替换、放弃和关闭时释放；确认直接提交这份快照。

## 验证边界与下一步

本机 Node 测试实际读取三种自建小图、中文与空格路径，并创建真实 Windows junction、移动来源和稀疏超限文件。来源时间变化/读取失败采用真实句柄上的故障注入；200MiB 精确边界验证预算逻辑，没有制作完整 200MiB 图片批次。跨专题 10,001 题使用两个真实文件执行准备链路。

第三批验证内部线程准备，见[第三批证据](../evidence/m1c/README.md)。第四批进一步验证 80 题与三种图片入库、来源移动后跨进程读回原字节，见[第四批证据](../evidence/m1d/README.md)。第五批验证窗口调用、三种小图实际解码与坏图提示、来源移动后重开显示，见[第五批证据](../evidence/m1e/README.md)。这不改变导入校验仅识别签名/头部尺寸的边界。
