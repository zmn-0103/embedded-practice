## 调用与数据流

后续主进程导入服务创建 `createImportPreparationService(reportError)`，调用 `prepare(绝对路径列表, signal?)`，取得完整批次快照或中文错误集合。不需要继续使用时调用并等待 `close()`。默认期限 120 秒，内部可传入其他合法期限以验证超时路径；它不是性能目标。

主进程校验并复制路径列表 → 创建固定 Node 工作线程 → 第二批 `prepareImport` 读取、解析、检查与计算哈希 → 转移图片缓冲区、回传快照 → 主进程校验回复与线程身份 → 等待线程停止 → 完成请求。

批量 Markdown 解析、文件与图片读取、尺寸检查及哈希在工作线程中执行。主进程仍校验回复结构、计数和关联；没有重复解析 Markdown、编码整篇文本或计算资源哈希。尚未测量最大批次的主进程校验耗时和内存峰值。

## 实现位置

| 文件 | 职责 |
|---|---|
| [工作线程协议](../../src/main/workers/import-protocol.ts) | 固定版本、严格请求/回复、线程身份、快照计数/资源/绑定校验与统一失败结构 |

| [任务调度器](../../src/main/workers/import-task-runner.ts) | 单活动任务、取消、期限、事件竞争、等待停止与清理；可用最小线程接口注入故障 |
| [生产服务工厂](../../src/main/services/library/import-preparation.ts) | 固定工作脚本、清空继承的 execArgv、跟踪原始文件描述符；不接收任意脚本入口 |

服务是内部组件；第五批正常启动时创建组合服务，经固定预加载 API 展示准备、取消与结果，不向窗口暴露路径或 SQL。内部测试仍通过构建入口调用，窗口测试另走真实桥接，不增加生产测试开关。

## 生命周期与失败

- 每个实例最多一个活动任务，第二个请求返回 `IMPORT_BUSY`；请求等待期间直到线程停止都保持忙碌。
- 已取消的信号不会创建线程；运行中取消、到期或关闭会停止线程。`close()` 可重复等待，关闭后新请求返回 `WORKER_CANCELLED` 和服务已关闭的说明。
- 成功回复、业务失败、无结果退出、构造失败、非法消息、运行错误、超时和取消只能结算一次；后续竞争事件不能覆盖结果。
- 正常收尾清除期限计时器、取消监听和线程事件。终止失败时返回需要重启的错误并封闭该实例，尽力取消线程对进程退出的引用，保留错误监听；不能声称该失败分支已确认线程停止。
- 内部诊断回调与业务结果分开，回调抛错不能阻止清理。第五批已由主入口传入现有诊断函数，并在正常退出时等待操作和服务收尾。

请求只接受一到 10,000 个绝对 `.md` 路径；实际重复文件/专题、文件存在性与 200MiB/题量限制仍由准备器负责。请求进入异步操作前复制，不随调用者后续修改而变化。

回复必须具有正确协议版本和对应线程 ID。校验包含严格字段、题量合计、唯一专题与资源哈希、图片绑定、三种图片格式、正尺寸、非空字节及大小限制。文本字符数与去重图片字节之和不得超过来源大小；字符数只是 UTF-8 字节下界。这里不重新证明 Markdown 语义、像素完整性或参考答案正确性。

## 字节与构建

图片来自第二批有界读取的自有 `Buffer.alloc` 缓冲区。工作入口对底层 ArrayBuffer 去重后转移，接收端保留 Uint8Array 和原始字节；不使用 JSON 或 base64 回传图片，不依赖来源路径继续可读。线程停止后，快照字节仍由调用方持有。

构建生成 `out/main/index.js`、`out/main/import-preparation.js`、带内容标识的工作脚本和共享依赖块。工作脚本路径由 electron-vite `?nodeWorker` 生成；开发构建和 ASAR 内使用同一相对引用。无需手改生成文件或放宽渲染权限。

本批实际重新生成 `release/win-unpacked/`，并在其 ASAR 内运行工作线程；静态提取 10 个构建文件与 `out/` 逐字节一致。旧 M0 NSIS 安装包未改，本批没有新安装包验收。
