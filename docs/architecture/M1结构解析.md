## 输入与结果

入口：[parse-question-bank.ts](../../src/main/services/library/parse-question-bank.ts) 的 `parseQuestionBank(input, fileName)` 接收已按 UTF-8 解码的文本和诊断文件名。外层准备器负责字节解码，工作线程服务执行后台任务；第五批由受限窗口文件选择触发。解析器不读取或修改来源文件，不访问数据库或网络。

成功结果包含专题元数据、有序题目和 Markdown 引用定义。每题包含稳定 ID、标题、标签、难度、题干/答案原始 Markdown、图片引用、来源行，以及第四批新增的本题实际使用的引用定义。正文只去除分区边界空行；内部换行、代码缩进和行尾双空格不改写。

失败结果只包含错误集合，不带部分题库。错误包含错误码、文件名、行、列与原因。意外解析异常转为文件级失败；本批没有主进程导入日志或界面错误展示入口。

## 模块职责

| 文件 | 当前职责 |
|---|---|
| [共享契约](../../src/shared/contracts/question-bank.ts) | 元数据 Schema、ID/难度规则、大小上限与只读结果类型 |
| [文档解析](../../src/main/services/library/markdown-document.ts) | unified + remark AST、GFM、YAML、BOM、版本/字段检查、HTML 拒绝与引用定义索引 |
| [题目前元数据](../../src/main/services/library/question-metadata.ts) | 限定区间内的标签、难度、重复字段和逐行定位 |
| [单题解析](../../src/main/services/library/parse-question.ts) | ID/标题、唯一且有序的三级分区、有效正文与原文切片 |
| [图片引用](../../src/main/services/library/image-references.ts) | 收集行内/引用式图片，进行路径与扩展名的词法检查 |
| [专题入口](../../src/main/services/library/parse-question-bank.ts) | 根节点分题、层级、空专题、题量、重复 ID、完整成功或完整失败 |

题目边界和分区来自 AST，不按字符串中的 `##` 切分。代码块内的伪标题、伪元数据和 HTML 示例均作为代码保留。引用定义采用 Markdown 规范与首个定义，导出为普通数据，避免题干/答案独立显示时失去题外定义；后续渲染仍需验证外链并把图片替换为受控资源 ID。

## 已检查与尚未检查

- 已检查：文件头、字段/版本/ID、正文分区、元数据、原始 HTML、20MiB 单文件与 10,000 题上限。
- 已静态检查图片：仅允许 `assets/` 内的 PNG/JPEG/WebP 引用，拒绝远程、绝对、越界、反斜线、控制字符、查询/片段与 Windows 尾点/尾空格歧义路径。
- 尚未检查图片：文件存在性、实际规范化路径/符号链接、文件签名、尺寸和 10MiB 限额。静态通过的路径不得直接用于任意文件读取。
- 外层已实现：文件/题量/大小限制、同批专题冲突、资源快照、工作线程，以及第四批的内容指纹、预览令牌/摘要、版本比较、事务提交、归档和图片入库；不属于纯解析入口职责。
- 第五批应用已接入受限导入 IPC、模板导出、窗口流程、受控图片显示与退出协调，见[窗口与受控内容](M1窗口与受控内容.md)；这些属于外层服务，不改变解析器边界。
- 不验证：参考答案的技术正确性、开发板接线或板上现象。相关条件来自用户题答和注明的资料。
